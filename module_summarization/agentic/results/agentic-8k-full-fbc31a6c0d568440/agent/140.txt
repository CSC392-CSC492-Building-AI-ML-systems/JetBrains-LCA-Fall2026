Short Overview of Dask Best Practices
=====================================

Partitioning Strategies
-----------------------

Constructing ordered (i.e., not hashed) partitions in Dask can be challenging, especially when dealing with generic objects or out-of-core computations. Calculating exact partition boundaries or precise percentiles is often difficult and computationally expensive. However, perfect partition boundaries are not always necessary for effective partitioning. Instead, aiming for a "good enough" method that scales well to many partitions and behaves robustly across various scenarios is recommended.

Two effective approaches to partitioning include:

1. **Subsampling Partitions:** Take a subsample from each partition and then determine new partition boundaries based on the combined subsamples.
2. **Percentile-Based Partitioning:** Calculate equally spaced percentiles within each partition (a relatively inexpensive operation) and merge these results to define partition boundaries.

Dask employs a hybrid approach using random percentiles rather than purely random samples. This method balances stability and scalability, especially when repartitioning data.

When the number of partitions remains constant, a ratio of 2:1 fixed percentiles to random percentiles is typically used. If repartitioning involves reducing from a very high number of partitions to a much lower number, more random percentiles are incorporated. This stochastic approach helps mitigate potential correlations in the data that might otherwise skew partition boundaries.

Deterministic Computations
--------------------------

Ensuring deterministic behavior in computations is a best practice in Dask workflows. For example, operations such as selecting the largest values (`nlargest`), dropping duplicates, or grouping and aggregating data should produce consistent task graphs across runs when given the same input data and parameters.

Deterministic task graphs facilitate debugging, caching, and reproducibility. Testing for deterministic behavior can involve comparing the sorted keys of the Dask graphs generated by identical operations to confirm they match, and verifying that different operations produce distinct graphs.

Summary
-------

- Aim for scalable, "good enough" partitioning methods rather than perfect partition boundaries.
- Use a combination of subsampling and percentile-based approaches, favoring random percentiles for stability.
- Adjust the ratio of fixed to random percentiles based on whether the number of partitions changes.
- Strive for deterministic task graphs to ensure reproducibility and ease of debugging.
- Validate deterministic behavior by comparing task graphs of repeated operations.

Following these best practices will help you build efficient, scalable, and reliable Dask workflows.
