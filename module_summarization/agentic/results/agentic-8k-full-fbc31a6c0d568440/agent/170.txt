Handling Large Datasets
=======================

When working with large spectral data cubes, memory management and computational efficiency become critical. The SpectralCube package provides tools and warnings to help users handle large datasets effectively and avoid common pitfalls related to memory usage.

Caching Function Calls
----------------------

To improve performance, some functions use caching to store results of expensive computations. The `cached` decorator is used internally to cache function calls based on their arguments, reducing redundant calculations and speeding up repeated operations.

Warnings for Potentially Slow or Memory-Intensive Operations
------------------------------------------------------------

Certain operations require loading the entire data cube into memory, which can be prohibitive for very large datasets. To help users avoid unintentional slowdowns or memory exhaustion, SpectralCube includes the `warn_slow` decorator that wraps such functions.

- If the cube is large (marked as `_is_huge`) and the user has not explicitly allowed huge operations (`allow_huge_operations=False`), the function will raise a `ValueError` to prevent loading the entire cube into memory.
- If the cube is not huge but the operation still requires loading the full cube, a `PossiblySlowWarning` is issued to alert the user that the operation may be slow.
- Users can bypass these warnings and enable the operation by setting `cube.allow_huge_operations = True`.
- Alternatively, users are encouraged to use memory-efficient approaches by specifying parameters such as `how='slice'` or `how='ray'` to avoid loading the entire cube at once.

For more details and best practices, see the online documentation:  
https://spectral-cube.readthedocs.io/en/latest/big_data.html

Custom Warning Classes
----------------------

SpectralCube defines several custom warning classes derived from `AstropyUserWarning` to provide informative messages related to large data handling and other issues:

- `PossiblySlowWarning`: Warns about operations that may be slow due to loading large data into memory.
- `UnsupportedIterationStrategyWarning`
- `VarianceWarning`
- `SliceWarning`
- `BeamAverageWarning`
- `BeamWarning`
- `WCSMismatchWarning`
- `NotImplementedWarning`
- `StokesWarning`
- `ExperimentalImplementationWarning`
- `SmoothingWarning`
- `NonFiniteBeamsWarning`
- `WCSWarning`
- `FITSWarning`
- `BadVelocitiesWarning`

These warnings help users identify potential problems or limitations when working with large or complex datasets.

Handling Huge Cubes
-------------------

SpectralCube internally tracks whether a cube is considered "huge" based on its size. When a cube is flagged as huge, certain operations that require loading the entire cube into memory are disabled by default to prevent excessive memory usage.

Users working with huge cubes can:

- Enable large operations explicitly by setting `cube.allow_huge_operations = True`.
- Use alternative methods that process the cube in smaller chunks or slices.
- Pay attention to warnings and errors raised when attempting memory-intensive operations.

Best Practices
--------------

- Avoid loading entire large cubes into memory when possible.
- Use slicing or ray-based methods (`how='slice'` or `how='ray'`) to process data incrementally.
- Monitor warnings and errors related to large data handling.
- Cache results of expensive computations when repeated calls are expected.
- Consult the online big data guide for detailed strategies and examples.

Summary
-------

Handling large spectral cubes efficiently requires careful management of memory and computation. SpectralCube provides built-in mechanisms to warn users about potentially slow or memory-heavy operations, decorators to cache results, and options to control behavior with huge datasets. By following recommended practices and leveraging these tools, users can work effectively with big data in spectral cube analysis.
