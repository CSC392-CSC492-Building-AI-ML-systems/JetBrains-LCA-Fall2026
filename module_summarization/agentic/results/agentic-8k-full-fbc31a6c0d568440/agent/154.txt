Connecting Steps Together
=========================

In a workflow graph, connecting steps together is essential to define the flow of data between processing units. This section describes how steps are connected, how connections are managed, and how parameters and metadata propagate through the graph.

Connecting Inputs and Outputs
-----------------------------

Connections between steps are established by linking outputs of one step to inputs of another. The core function responsible for this is `connect`, which takes two handles representing the endpoints of the connection.

Each handle is a tuple consisting of:

- The step name
- The direction (`'inputs'` or `'outputs'`)
- The handle name (input or output name)

The `connect` function ensures that connections are only made from an output to an input, enforcing the directionality of data flow. It identifies the source (output) and destination (input) handles, then creates an `Edge` object representing the connection. This edge is stored internally in dictionaries tracking incoming (`_edges_i`) and outgoing (`_edges_o`) edges for each step.

Connecting by Name
------------------

To simplify connecting steps, the `connect_by_name` function allows connecting two steps by automatically matching outputs of the source step to inputs of the destination step that share the same name.

This function accepts either step objects or step names. It retrieves the corresponding step objects, verifies their presence in the graph, and then finds the intersection of output names from the source step and input names from the destination step. For each matching name, it calls `connect` to establish the connection.

Parameter Management
--------------------

Parameters can be updated and expanded across all steps in the graph using the following functions:

- `update_params(params)`: Updates parameters for every step by calling each step's `update_params` method with the provided parameter dictionary.
- `expand_params()`: Calls each step's `expand_params` method to process or expand parameters as needed.

These functions ensure consistent parameter propagation and management throughout the workflow.

Metadata Handling
-----------------

Metadata about connections and build information is maintained and can be dumped to steps using the `dump_metadata_to_steps` function. This function collects incoming and outgoing edges for each step, organizing them by input and output handles.

For each edge, metadata includes:

- The connected handle name (`f`)
- The build directory of the connected step (`step`)

Additionally, build directories and build IDs for each step are included in the metadata. This information is useful for tracking dependencies, build environments, and for debugging purposes.

Summary
-------

- Connections are made from outputs to inputs using `connect`.
- `connect_by_name` automates connections by matching handle names.
- Parameters are updated and expanded across all steps.
- Metadata about connections and builds is collected and associated with each step.

This system ensures a robust and clear definition of data flow and dependencies within the workflow graph.
