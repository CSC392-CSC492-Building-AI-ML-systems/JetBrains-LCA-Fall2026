Examples and Usage
==================

This section provides examples and usage details for various field types available in the library.

Integer Fields
--------------

### IntField

An integer field representing a 32-bit signed integer.

- `pk` (bool): Set to `True` if this field is a Primary Key.

Example:

```python
from tortoise import fields

class MyModel(Model):
    id = fields.IntField(pk=True)
    age = fields.IntField()
```

### BigIntField

A big integer field representing a 64-bit signed integer.

- `pk` (bool): Set to `True` if this field is a Primary Key.

Example:

```python
class MyModel(Model):
    id = fields.BigIntField(pk=True)
    large_number = fields.BigIntField()
```

### SmallIntField

A small integer field representing a 16-bit signed integer.

- `pk` (bool): Set to `True` if this field is a Primary Key.

Example:

```python
class MyModel(Model):
    id = fields.SmallIntField(pk=True)
    small_number = fields.SmallIntField()
```

Character Fields
----------------

### CharField

A character field with a maximum length.

- `max_length` (int): Maximum length of the field in characters. Must be >= 1.

Example:

```python
class MyModel(Model):
    name = fields.CharField(max_length=50)
```

### TextField

A large text field for storing long strings.

Example:

```python
class MyModel(Model):
    description = fields.TextField()
```

Enum Fields
-----------

### IntEnumField

An integer enumeration field representing an integer enum.

- `enum_type` (Type[IntEnum]): The enum class.
- `description` (Optional[str]): Description of the field. If not specified, it is automatically generated as a multiline list of "name: value" pairs.

Example:

```python
from enum import IntEnum

class Status(IntEnum):
    PENDING = 1
    COMPLETED = 2
    FAILED = 3

class MyModel(Model):
    status = fields.IntEnumField(Status)
```

### CharEnumField

A character enumeration field representing a character enum.

- `enum_type` (Type[Enum]): The enum class.
- `description` (Optional[str]): Description of the field.
- `max_length` (int): Maximum length of the field. If zero or not specified, the size is automatically detected.

Example:

```python
from enum import Enum

class Color(Enum):
    RED = "red"
    GREEN = "green"
    BLUE = "blue"

class MyModel(Model):
    color = fields.CharEnumField(Color, max_length=5)
```

Field Description Dictionary
----------------------------

Each field provides a description dictionary that can be serialized to JSON or returned as raw Python objects.

When `serializable=True` (default), the dictionary contains JSON-serializable data:

```python
{
    "name": str,               # Field name
    "field_type": str,         # Field type
    "db_column": str,          # Name of DB column

    # Optional: Only for pk/data fields
    "raw_field": str,          # Name of raw field of the Foreign Key

    # Optional: Only for Foreign Keys
    "db_field_types": dict,    # DB Field types for default and DB overrides
    "python_type": str,        # Python type
    "generated": bool,         # Is the field generated by the DB?
    "nullable": bool,          # Is the column nullable?
    "unique": bool,            # Is the field unique?
    "indexed": bool,           # Is the field indexed?
    "default": ...,            # The default value (coerced to int/float/str/bool/null)
    "description": str,        # Description of the field (nullable)
    "docstring": str,          # Field docstring (nullable)
}
```

When `serializable=False`, some fields are returned as native Python objects:

```python
{
    "field_type": Field,       # The Field class used
    "python_type": Type,       # The actual Python type
    "default": ...,            # The default value as native type OR a callable
}
```

This allows for flexible introspection and serialization of field metadata.

Notes
-----

- Primary key fields often have database-generated values, indicated by the `generated` attribute.
- Constraints such as minimum and maximum values are available via the `constraints` property on numeric fields.
- Enum fields automatically generate descriptions listing their possible values.
- Character enum fields automatically detect the required maximum length if not specified, but schema updates may be necessary if the enum changes.

These fields integrate seamlessly with the ORM models, providing type safety, validation, and database compatibility.
