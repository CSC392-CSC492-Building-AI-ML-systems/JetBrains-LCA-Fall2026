Using Lists
===========

This section describes how to work with lists of components and related objects within the API.

Component Availability for Lists
--------------------------------

The API provides methods to retrieve availability information for components, either individually or in lists.

### `get_component_availability(component, locations=None)`

Return the availability of a single *component*.

- **component**: The component to check availability for.
- **locations** (optional): Limit the availability check to these locations.

Returns a dictionary mapping `{location_id: percentage_availability}` for the specified component.

### `get_component_availabilities(components, locations=None)`

Return availability information for a list of *components*.

- **components**: A list of components to check availability for.
- **locations** (optional): Limit the availability check to these locations.

Returns a list of dictionaries, each corresponding to a component in the input list. Each dictionary maps `{location_id: percentage_availability}`.

This method optimizes queries by separating components into containers (those with members) and standard components. For container components, availability is calculated as the average availability of its members.

Availability percentages are rounded and clamped between 0 and 100 to avoid quantization errors.

Sending Invites to Lists of Review Session Invitees
---------------------------------------------------

The API supports sending invites to review sessions for single or multiple invitees.

### `send_review_session_invite(invitee)`

Send an invite to a review session to a single *invitee*.

- **invitee**: An instance of `ReviewSessionInvitee`. The invitee must be committed before sending.

### `send_review_session_invites(invitees)`

Send invites to a review session to a list of *invitees*.

- **invitees**: A list of `ReviewSessionInvitee` objects. All invitees must be committed before sending.

This method batches the invite sending operations and calls the server once. If the server does not support the action, an informative error is raised advising to update the server.

Context Managers for Temporary List-Related Settings
----------------------------------------------------

The API includes context managers to temporarily change session settings that may affect list operations.

### `AutoPopulatingContext(session, auto_populate)`

Context manager to temporarily change the session's `auto_populate` setting.

Usage:

```python
with AutoPopulatingContext(session, True):
    # Operations with auto_populate enabled
```

### `OperationRecordingContext(session, record_operations)`

Context manager to temporarily change the session's `record_operations` setting.

Usage:

```python
with OperationRecordingContext(session, True):
    # Operations with recording enabled
```

These context managers ensure that the original session settings are restored after the block is exited.

Summary
-------

Working with lists in the API involves handling collections of components or invitees efficiently. The provided methods and context managers facilitate batch operations, availability checks, and temporary configuration changes to optimize list handling and server interactions.
