Library Conventions
===================

This library follows a set of conventions to ensure consistency and compatibility across its various components and with other tools. The conventions cover default settings for plotting, state space representations, and version compatibility.

Default Settings
----------------

The library provides several preset configurations to match common conventions used in control systems analysis and design.

### MATLAB-Compatible Defaults

Use the MATLAB-compatible configuration settings by calling `use_matlab_defaults()`. These conventions include:

- Bode plots display gain in decibels (dB), phase in degrees, and frequency in radians per second.
- Plots include grids by default.
- State space classes and functions use Numpy `matrix` objects for matrix representations.

### FeedBack Systems (FBS) Defaults

Use the FeedBack Systems (FBS) compatible settings by calling `use_fbs_defaults()`. These conventions include:

- Bode plots display gain in powers of ten (linear scale), phase in degrees, and frequency in radians per second.
- No grid is shown on plots by default.
- Nyquist plots use dashed lines for the mirror image of the Nyquist curve.

State Space Representation
--------------------------

The library supports two types of matrix representations for state space operations: Numpy `matrix` and 2D Numpy `ndarray`.

### Using Numpy Matrix

The function `use_numpy_matrix(flag=True, warn=True)` controls whether the deprecated Numpy `matrix` class is used for state space operations.

- If `flag` is `True` (default), the library uses the Numpy `matrix` class.
- If `flag` is `False`, matrices are represented by 2D Numpy `ndarray` objects.
- If `warn` is `True` (default), a deprecation warning is issued when enabling the use of Numpy `matrix`.

**Note:** Starting from release 0.9.0, the default matrix type for state space operations is the 2D Numpy `ndarray`. The use of Numpy `matrix` is deprecated.

Version Compatibility
---------------------

The library allows setting default configurations to match those used in previous releases via the function `use_legacy_defaults(version)`. This function accepts a version string (e.g., `'0.1'` to `'0.8.4'`) and adjusts the defaults accordingly.

The version string can be in various formats, including:

- Early release tags like `REL-0.N`, `control-0.Np`, or `v0.Np` where `N` is a number and `p` is a patch letter.
- Standard version formats like `vM.N.P` or `M.N.P`.

If the version string is not recognized, a `ValueError` is raised.

Additional Default Settings
---------------------------

Some other default settings managed by the library include:

- Default timestep for control systems (`default_dt`), which switched to `None` (continuous time) as default.
- Naming conventions for input-output systems (`iosys`), including delimiters and prefixes/suffixes for duplicate or linearized system names.
- Behavior of state space operations such as whether to remove useless states.
- Behavior of forced response functions, such as whether to return the state vector `x` by default.

Plotting Conventions
--------------------

The library's plotting functions adhere to the conventions set by the chosen defaults (MATLAB or FBS). These include units for gain, phase, frequency, and the presence or absence of grids on plots.

Summary
-------

By using the provided functions to set defaults, users can easily switch between different conventions to match their preferred tools or literature standards. The library also supports backward compatibility with older versions through legacy default settings.

For detailed usage of these functions and their parameters, refer to the respective function documentation within the library.
