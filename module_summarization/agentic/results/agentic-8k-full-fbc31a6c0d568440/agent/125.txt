FITS Headers
============

Overview
--------

FITS (Flexible Image Transport System) headers are an essential part of FITS files, containing metadata about the data stored in the file. Each header consists of a series of keyword-value pairs, known as "cards," which describe the properties of the data, such as dimensions, data type, and other relevant information.

Header Structure and Functionality
----------------------------------

The `Header` class represents a FITS header and provides a dictionary-like interface to access and manipulate the header cards. It supports operations such as adding, updating, and removing cards, as well as iterating over keys, values, and items.

Key features include:

- Creation of headers from keys with optional default values and comments.
- Support for duplicate keywords, accessible via indexed keys.
- List-like and dictionary-like methods for manipulating header cards, including `pop`, `setdefault`, and `update`.
- Preservation of the order of cards, which is important for FITS compliance.
- Ability to handle comments associated with each keyword.

Example usage:

```python
header = fits.Header.fromkeys(["A", "B"], "C")
assert header["A"] == "C"
assert header.comments["A"] == ""
```

Handling Duplicate Keywords
---------------------------

FITS headers may contain duplicate keywords. The `Header` class supports this by allowing access to specific instances of a keyword using a tuple key, e.g., `("A", 0)` for the first occurrence of keyword "A". This enables precise control over headers with repeated keywords.

Header Iteration and Access
---------------------------

The `Header` class supports iteration over keys, values, and items, allowing easy traversal and inspection of header contents:

- `keys()` and iteration over the header yield the keywords.
- `values()` yields the corresponding values.
- `items()` yields `(keyword, value)` pairs.

Modification Methods
--------------------

Headers can be modified using methods such as:

- `pop(key)`: Removes and returns the value associated with `key`.
- `setdefault(key, default)`: Returns the value for `key` if it exists; otherwise, inserts `key` with the value `default`.
- `update(dict)`: Updates the header with key-value pairs from a dictionary, adding new cards or updating existing ones.

FITS Header Cards and Validation
--------------------------------

Certain keywords are mandatory or have specific requirements depending on the HDU (Header/Data Unit) type. The header classes include verification methods to ensure compliance with FITS standards, such as checking the presence and validity of keywords like `PCOUNT` and `GCOUNT` in extension HDUs.

Extension HDUs and Nonstandard Extensions
-----------------------------------------

Extension HDUs are additional data units in a FITS file beyond the primary HDU. The `ExtensionHDU` class serves as a base for standard extension types such as `TableHDU`, `ImageHDU`, and `BinTableHDU`. It provides methods for writing the extension to a file and verifying header integrity.

Nonstandard extensions, which have non-standard `XTENSION` keyword values, are handled by the `NonstandardExtHDU` class. This class reads the data as a raw byte stream and is used when the extension type is not recognized as one of the standard types (`IMAGE`, `TABLE`, `BINTABLE`, `A3DTABLE`).

Header Parsing and Formatting
-----------------------------

The `HeaderFormatter` and its subclass `TableHeaderFormatter` provide functionality to convert FITS headers into table-like structures for easier analysis and manipulation. The `TableHeaderFormatter` produces tables with columns such as filename, HDU index, keyword, and value, facilitating inspection of headers across multiple files or HDUs.

Exceptions
----------

- `InvalidHDUException`: Raised when an HDU is determined to be invalid or corrupted based on its header.

Summary
-------

FITS headers are a critical component of FITS files, encapsulating metadata in a structured and standardized way. The provided classes and methods enable robust creation, manipulation, validation, and parsing of FITS headers, supporting both standard and nonstandard extensions. This functionality ensures that FITS files can be accurately interpreted and modified while maintaining compliance with the FITS standard.
