PostgresEngine
==============

The `PostgresEngine` class provides an asynchronous interface for connecting to and interacting with a PostgreSQL database using the `asyncpg` driver. It supports connection pooling, transaction management, and extension handling, making it suitable for high-performance applications requiring asynchronous database operations.

Initialization
--------------

To create an instance of `PostgresEngine`, provide a configuration dictionary with connection parameters such as host, port, user, password, and database name. Additional optional parameters allow customization of extensions, logging, and read replicas.

```python
engine = PostgresEngine(
    config={
        'host': 'localhost',
        'port': 5432,
        'user': 'username',
        'password': 'password',
        'database': 'mydb',
    },
    extensions=('uuid-ossp',),
    log_queries=False,
    log_responses=False,
    extra_nodes=None,
)
```

Parameters:

- **config** (`dict`): Connection parameters passed to `asyncpg`. Common keys include `host`, `port`, `user`, `password`, and `database`. See the [asyncpg documentation](https://magicstack.github.io/asyncpg/current/api/index.html#connection) for all options.

- **extensions** (`Sequence[str]`, default `('uuid-ossp',)`): PostgreSQL extensions to create on startup. Set to an empty tuple `()` for read-only databases.

- **log_queries** (`bool`, default `False`): If `True`, all SQL and DDL statements are logged before execution.

- **log_responses** (`bool`, default `False`): If `True`, raw responses from queries are logged.

- **extra_nodes** (`Mapping[str, PostgresEngine]`, optional): Additional database nodes such as read replicas. Each node is a mapping from a name to a `PostgresEngine` instance. Useful for directing queries to replicas.

Example of using extra nodes:

```python
DB = PostgresEngine(
    config={'database': 'main_db'},
    extra_nodes={
        'read_replica_1': PostgresEngine(
            config={
                'database': 'main_db',
                'host': 'read_replicate.my_db.com',
            },
            extensions=(),
        )
    }
)
```

You can specify which node to run a query against by passing the `node` parameter:

```python
await MyTable.select().run(node="read_replica_1")
```

Version Handling
----------------

The engine provides a method to retrieve the PostgreSQL server version:

```python
version = await engine.get_version()
```

This method returns the major and minor version as a float (e.g., `12.4`). It handles different version string formats returned by PostgreSQL.

Transaction Management
======================

The `PostgresTransaction` class provides an asynchronous context manager for managing database transactions. It supports nested transactions via savepoints and ensures proper commit or rollback behavior.

Usage:

```python
async with engine.transaction():
    # Run queries within the transaction
    await Band.select().run()
```

Features:

- Supports nested transactions by default. Nested transactions create savepoints to allow partial rollbacks.

- Optionally disallow nested transactions by setting `allow_nested=False` when creating a transaction.

- Automatically commits the transaction if no exceptions occur, otherwise rolls back.

- Provides methods to manually commit, rollback, or rollback to a savepoint.

Example:

```python
async with engine.transaction():
    # Perform database operations
    await SomeTable.insert(...).run()
```

Savepoints
----------

Within a transaction, savepoints can be created and managed to allow partial rollbacks:

```python
savepoint = await transaction.savepoint(name="my_savepoint")
# ... perform some operations
await savepoint.rollback_to()
```

This allows rolling back to a specific point within a transaction without aborting the entire transaction.

Connection Handling
===================

The engine manages connections via an optional connection pool. If a pool is configured, connections are acquired and released automatically. Otherwise, new connections are created and closed as needed.

Logging
=======

- When `log_queries` is enabled, all SQL and DDL statements are printed before execution.

- When `log_responses` is enabled, raw responses from queries are printed for debugging purposes.

Context Variable
================

The engine maintains a context variable `current_transaction` to track the active transaction within the current asynchronous context. This enables nested transaction support and proper transaction scoping.

Error Handling
==============

- Attempting to create a nested transaction when `allow_nested=False` raises a `TransactionError`.

- Connection errors during version retrieval are caught and logged as warnings, preventing import-time failures.

Summary
=======

The `PostgresEngine` module provides a robust, asynchronous PostgreSQL client with support for:

- Connection pooling and configuration

- Extension management

- Query and response logging

- Multiple database nodes (e.g., read replicas)

- Transaction management with nested transactions and savepoints

- Version detection and error handling

This makes it a powerful tool for building scalable, asynchronous applications that interact with PostgreSQL databases.
