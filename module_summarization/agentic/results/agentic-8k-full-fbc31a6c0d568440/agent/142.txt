dask.delayed
=============

The `dask.delayed` interface provides a simple way to build task graphs by delaying the evaluation of Python functions and expressions. It allows you to write normal Python code but defer execution until explicitly requested, enabling parallel and distributed computation.

Key Concepts
------------

- **Delayed Objects**: Wrapping a function or value with `delayed` creates a `Delayed` object representing a lazy computation.
- **Task Graphs**: `Delayed` objects internally build a task graph representing the computation dependencies.
- **Purity**: By default, delayed functions are assumed pure (deterministic and side-effect free), enabling caching and reuse of intermediate results.
- **Computation**: Calling `.compute()` on a `Delayed` object triggers execution of the task graph and returns the computed result.

Creating Delayed Objects
------------------------

You can create delayed objects by decorating functions or wrapping values:

```python
from dask import delayed

@delayed
def add(x, y):
    return x + y

a = delayed(1)
b = delayed(2)
result = add(a, b)
```

Alternatively, wrap existing functions or values:

```python
add = delayed(lambda x, y: x + y)
a = delayed(1)
b = delayed(2)
result = add(a, b)
```

Delayed objects can also be created from collections or complex Python objects, with nested delayed computations automatically handled.

Purity and Key Naming
---------------------

By default, delayed functions are considered *pure*, meaning that the same inputs always produce the same outputs. This allows Dask to reuse intermediate results and generate consistent keys for caching.

- The `pure` keyword argument controls this behavior:

  - `pure=True` (default): keys are generated by hashing the function and arguments.
  - `pure=False`: keys are randomly generated, disabling caching.

- You can explicitly specify the key name using the `dask_key_name` keyword argument:

```python
result = add(1, 2, dask_key_name='my_key')
```

Note that keys must be unique for different computations to avoid incorrect caching.

Delayed Objects as Proxies
--------------------------

Delayed objects act as proxies to the underlying values and support many Python operations lazily:

```python
a = delayed([1, 2, 3])
b = a + [4, 5]
print(b.compute())  # Output: [1, 2, 3, 4, 5]

print(a[1].compute())  # Output: 2

print(a.count(2).compute())  # Output: 1
```

Method calls and attribute access are also supported lazily. Errors due to missing attributes or methods will only be raised at compute time.

Handling Impure Functions and Methods
------------------------------------

- Magic methods (e.g., operators, attribute access) are assumed pure and cannot override purity via `delayed`.
- To handle impure methods or attributes, wrap them in a delayed function with `pure=False`:

```python
class Incrementer:
    def __init__(self):
        self._n = 0
    @property
    def n(self):
        self._n += 1
        return self._n

x = delayed(Incrementer())
print(x.n.key == x.n.key)  # True, assumed pure

get_n = delayed(lambda obj: obj.n, pure=False)
print(get_n(x).key == get_n(x).key)  # False, impure
```

- Methods are assumed impure by default; to assume purity, specify `pure=True`:

```python
a.count(2, pure=True).key == a.count(2, pure=True).key  # True
```

Unpacking and Normalizing Tasks
-------------------------------

The `unpack_collections` function normalizes Python objects by:

- Replacing `Delayed` objects with their keys.
- Converting literals to scheduler-friendly formats.
- Extracting and merging Dask graphs from nested collections.

This function supports most built-in Python types, including lists, tuples, sets, dicts, slices, dataclasses, and namedtuples.

Example:

```python
from dask import delayed, unpack_collections

a = delayed(1, 'a')
b = delayed(2, 'b')
task, collections = unpack_collections([a, b, 3])
print(task)        # ['a', 'b', 3]
print(collections) # (Delayed('a'), Delayed('b'))
```

Finalizing Computations
-----------------------

The `finalize` function wraps a Dask collection to produce a `Delayed` object representing the final computation:

```python
final = finalize(collection)
```

This is useful for integrating with other Dask collections and workflows.

Tokenization and Key Generation
-------------------------------

The `tokenize` function generates consistent keys for tasks based on their inputs:

```python
from dask.delayed import tokenize

key = tokenize(obj, pure=True)
```

- If `pure=True`, a consistent hash is generated.
- If `pure=False`, a unique random identifier is generated.

This function is used internally by `delayed` to generate keys for caching and graph construction.

Deprecated Functions
--------------------

The `to_task_dask` function is deprecated in favor of `unpack_collections`. It previously normalized Python objects and merged subgraphs into a single Dask graph.

Summary
-------

The `dask.delayed` interface provides a powerful and flexible way to build lazy, parallel computations in Python by:

- Wrapping functions and values as delayed objects.
- Automatically constructing task graphs.
- Supporting purity and caching semantics.
- Allowing fine control over key naming and computation behavior.
- Integrating seamlessly with other Dask collections.

This interface enables scalable and efficient computation with minimal changes to existing Python code.
