PyTables File Format
====================

Overview
--------

PyTables is a package for managing hierarchical datasets and designed to efficiently and easily cope with extremely large amounts of data. It is built on top of the HDF5 library and NumPy package, providing a high-level interface to organize, manipulate, and retrieve data stored in HDF5 files.

The PyTables file format is based on HDF5, which organizes data in a filesystem-like hierarchy of groups and datasets. PyTables extends this with additional structures and metadata to support advanced features such as indexing, compression, and querying.

Indexing in PyTables
--------------------

One of the key features of PyTables is its support for indexing columns in tables to speed up data retrieval. The indexing mechanism is implemented through the `Index` class, which manages the index information for a specific column in a table.

### The Index Class

The `Index` class represents the index of a column in a table. It is a specialized subclass of the `Group` class, enriched with indexing capabilities. Each `Index` instance is associated with exactly one column in a table.

#### Key Attributes

- **kind**: Specifies the kind of index, which determines the granularity and size of the index. Possible values are:
  - `'ultralight'` (1 byte per index element)
  - `'light'` (2 bytes)
  - `'medium'` (4 bytes)
  - `'full'` (8 bytes)

- **filters**: An instance of the `Filters` class that defines the compression and other I/O filters applied to the index datasets.

- **dirty**: A boolean flag indicating whether the index is out of sync with the underlying column data. Dirty indexes exist but are not usable until updated.

- **column**: The `Column` object associated with this index.

- **table**: The `Table` object to which the indexed column belongs.

- **nrows**, **nelements**: The number of slices and total indexed rows in the index.

- **blocksizes**: A tuple defining the sizes of various compound blocks used internally by the index:
  - `superblocksize`
  - `blocksize`
  - `slicesize`
  - `chunksize`

- **optlevel**: The optimization level used for the index, affecting performance and storage trade-offs.

- **byteorder**: The byte order ('little' or 'big') of the index datasets on disk.

- **indsize**: The size in bytes of each index element, derived from the index kind.

#### Internal Structure

The index data is organized hierarchically into superblocks, blocks, slices, and chunks:

- **Superblock**: The largest unit, composed of multiple blocks.
- **Block**: Contains multiple slices.
- **Slice**: Contains multiple chunks.
- **Chunk**: The smallest unit of data indexing.

This hierarchical structure allows efficient searching and updating of the index.

#### Index Arrays and Caches

The `Index` class maintains several arrays and caches to optimize indexing operations:

- **sorted**: An `IndexArray` holding the sorted values of the indexed column.

- **indices**: An `IndexArray` storing the chunk numbers corresponding to the sorted values.

- **ranges**: A `CacheArray` caching range values for quick lookups.

- **mranges**: An `EArray` storing median ranges.

- **bounds**: A `CacheArray` caching boundary values for slices.

- **abounds**, **zbounds**, **mbounds**: `EArray`s storing start, end, and median bounds respectively.

These structures facilitate fast searching, sorting, and updating of indexes.

Indexing Policies and Defaults
------------------------------

- **default_auto_index**: By default, indexes are automatically updated after table append operations or reindexed after operations that invalidate the index.

- **default_index_filters**: The default compression filters applied to indexes use zlib compression at level 1 with shuffle enabled for performance and compression efficiency.

Supported Data Types for Optimized Search
------------------------------------------

PyTables implements optimized search algorithms for the following data types:

- Signed integers: int8, int16, int32, int64
- Unsigned integers: uint8, uint16, uint32, uint64
- Floating point: float32, float64

These optimizations improve the performance of index-based queries.

Versioning
----------

Indexes in PyTables have version identifiers to manage compatibility and features:

- Version "2.1" corresponds to PyTables Pro 2.1 and later series, including the join 2.3 Standard + Pro version.

Temporary Files
---------------

For certain index kinds and optimization levels, temporary files may be required during index building or updating. This is typically the case for indexes with item sizes greater than 1 byte, optimization levels above zero, and tables with more rows than the slice size.

Usage Notes
-----------

- The `Index` class is primarily intended for internal use within PyTables, but some of its attributes and methods are exposed for advanced users who need to interact directly with index structures.

- Indexes must be kept in sync with the underlying table data to ensure query correctness. The `dirty` flag indicates when an index needs to be rebuilt or updated.

- The hierarchical block structure and caching mechanisms are designed to balance memory usage and performance, enabling PyTables to handle very large datasets efficiently.

Summary
-------

PyTables extends the HDF5 file format with powerful indexing capabilities to accelerate data retrieval in large tabular datasets. The `Index` class encapsulates the complex internal structures and algorithms needed to maintain and query these indexes efficiently. Through configurable parameters such as index kind, optimization level, and filters, PyTables provides flexible and performant indexing tailored to diverse application needs.
