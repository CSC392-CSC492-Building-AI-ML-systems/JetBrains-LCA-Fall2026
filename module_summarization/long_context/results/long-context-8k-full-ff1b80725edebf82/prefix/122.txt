Unified Renderable Interface
============================

This module provides a unified interface for rendering components in Django applications, centered around the concept of a **Renderable** object. The interface is designed to simplify rendering templates with context data and managing CSS classes in a consistent and extensible manner.

AbstractRenderable
------------------

The `AbstractRenderable` class is the core of the renderable interface. It defines an abstract base class for objects that can render themselves using Django templates.

### Key Features

- **Template Selection**  
  The `get_template_names()` method returns the template name(s) to be used for rendering. By default, it returns the class attribute `template_name`. If no template name is set, it raises a `NotImplementedError`, requiring subclasses to specify a template.

- **Context Data**  
  The `get_context_data(request=None)` method returns the context dictionary passed to the template. By default, it returns a dictionary with a single key `'me'` pointing to the renderable instance itself.

- **Rendering**  
  The `render(request=None, extra_context_data=None)` method renders the template with the context data. It accepts an optional `request` object, which is forwarded to both `get_context_data` and Django's `render_to_string` function. Additional context data can be passed via `extra_context_data`.

Example usage:

```python
class MyRenderable(AbstractRenderable):
    template_name = 'my_template.html'

    def get_context_data(self, request=None):
        context = super().get_context_data(request=request)
        context['extra'] = 'value'
        return context
```

AbstractRenderableWithCss
-------------------------

`AbstractRenderableWithCss` extends `AbstractRenderable` by adding a unified API for managing CSS classes associated with the rendered component.

### CSS Classes API

- **Base and Extra CSS Classes**  
  - `get_base_css_classes_list()` returns a list of base CSS classes.  
  - `get_extra_css_classes_list()` returns a list of additional CSS classes.  
  Both methods return empty lists by default and can be overridden.

- **Combined CSS Classes**  
  - `get_css_classes_list()` returns the combined list of CSS classes by concatenating the base and extra CSS classes.  
  This method should be overridden to customize the CSS classes.

- **CSS Classes String**  
  - The `css_classes` property returns the CSS classes as a single string, joining the list with spaces.  
  - It also includes test-specific CSS classes if the setting `DJANGO_CRADMIN_INCLUDE_TEST_CSS_CLASSES` is enabled. These test classes are generated by filtering suffixes returned from `get_test_css_class_suffixes_list()` through a template tag.

- **Deprecated Method**  
  - `get_css_classes_string()` is deprecated in favor of the `css_classes` property.

Example usage:

```python
class MyCssRenderable(AbstractRenderableWithCss):
    def get_base_css_classes_list(self):
        return ['base-class']

    def get_extra_css_classes_list(self):
        return ['extra-class']

    def get_test_css_class_suffixes_list(self):
        return ['mycomponent']
```

AbstractBemRenderable
---------------------

`AbstractBemRenderable` is an alternative base class for renderables that use the BEM (Block Element Modifier) methodology for CSS class naming. It provides a natural way to work with BEM conventions.

### Initialization Parameters

- `bem_block` (str): The BEM block name. Cannot be supplied together with `bem_element`.
- `bem_element` (str): The BEM element name, which must contain a double underscore (`__`). Cannot be supplied together with `bem_block`.
- `bem_variant_list` (list): A list of BEM variant suffixes (modifiers) without the block/element prefix.
- `extra_css_classes_list` (list): Additional CSS classes to include.

### BEM CSS Classes API

- `get_bem_block()` returns the BEM block string.
- `get_bem_element()` returns the BEM element string.
- `get_bem_variant_list()` returns the list of BEM variants.
- `get_extra_css_classes_list()` returns extra CSS classes.
- `bem_block_or_element` property returns the block if set, otherwise the element.

### CSS Classes Property

- The `css_classes` property returns a string of CSS classes constructed according to BEM conventions:
  - The block or element name.
  - Variants appended as `block--variant` or `element--variant`.
  - Extra CSS classes.
  - Test CSS classes if enabled via settings.

### Validation

- Raises `ValueError` if both `bem_block` and `bem_element` are supplied.
- Raises `ValueError` if `bem_element` does not contain `__`.

Example usage:

```python
renderable = AbstractBemRenderable(
    bem_block='button',
    bem_variant_list=['primary', 'large'],
    extra_css_classes_list=['custom-class']
)
print(renderable.css_classes)
# Output: "button button--primary button--large custom-class"
```

Summary
-------

The unified renderable interface provides a flexible and consistent way to:

- Define renderable components with template and context management.
- Manage CSS classes either through a simple list-based API (`AbstractRenderableWithCss`) or a BEM-oriented API (`AbstractBemRenderable`).
- Include test-specific CSS classes conditionally.
- Render components easily with optional request context.

This interface encourages clean separation of rendering logic and styling concerns, facilitating maintainable and reusable UI components in Django projects.
