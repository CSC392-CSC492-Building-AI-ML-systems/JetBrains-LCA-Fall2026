Decision Trees
==============

Decision Trees are a versatile and widely used class of supervised learning algorithms for classification and regression tasks. They work by recursively partitioning the input space into subsets based on feature values, aiming to create homogeneous groups with respect to the target variable.

Overview
--------

This implementation of Decision Trees is designed with efficiency and flexibility in mind, supporting multiple outputs and handling missing values gracefully. The core of the tree-building process relies on impurity criteria to evaluate the quality of splits and to guide the recursive partitioning.

Impurity Criteria
-----------------

The impurity criterion is a fundamental component that measures how well a split separates the data into homogeneous subsets. This implementation defines an abstract interface `Criterion` that encapsulates methods for:

- Initializing the criterion with the target values, sample weights, and sample indices.
- Resetting and updating statistics as the tree grows.
- Computing node impurity and children impurities.
- Calculating node values for prediction.
- Handling monotonicity constraints.
- Managing missing values during split evaluation.

The impurity improvement is computed as the weighted decrease in impurity after a split, guiding the selection of the best split at each node.

Classification Criterion
------------------------

For classification tasks, the `ClassificationCriterion` class extends the abstract `Criterion` interface. It supports multiple outputs and multiple classes per output. Key features include:

- Counting weighted class frequencies for samples in the current node.
- Efficiently updating class counts when samples are moved between child nodes during split evaluation.
- Handling missing values by distributing them either to the left or right child node, depending on the split strategy.
- Computing impurity measures based on class distributions.

Handling Missing Values
-----------------------

Missing values in features are handled explicitly by maintaining separate sums for missing samples (`sum_missing`) and distributing these sums appropriately during split evaluation. This allows the tree to consider splits that send missing values to either the left or right child, improving robustness.

Monotonicity Constraints
------------------------

The implementation supports monotonicity constraints, which enforce that the predicted values respect a specified monotonic relationship with certain features. The criterion includes methods to check whether a proposed split satisfies these constraints by comparing node values against bounds and monotonicity directions.

Performance Considerations
--------------------------

- The code uses Cython and low-level memory operations (`memcpy`, `memset`) for efficient manipulation of arrays and statistics.
- Weighted samples are supported, allowing for flexible handling of sample importance.
- The impurity improvement proxy is used to speed up the search for the best split by quickly estimating the potential gain without computing full impurity values.

Summary
-------

Decision Trees in this implementation provide a powerful and efficient framework for supervised learning, supporting multi-output tasks, weighted samples, missing values, and monotonicity constraints. The modular design of impurity criteria allows for extensibility and customization to various learning problems.
