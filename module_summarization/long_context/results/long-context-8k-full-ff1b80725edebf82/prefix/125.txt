FITS Headers
============

The FITS (Flexible Image Transport System) header is a fundamental component of FITS files, containing metadata that describes the data stored in the file. This documentation provides an overview of the classes, functions, and utilities related to FITS header verification and manipulation.

Verification of FITS Headers
----------------------------

The verification framework ensures that FITS headers conform to expected standards and formats. It provides mechanisms to check for errors, warnings, and to optionally fix issues found in the headers.

### Exceptions and Warnings

- **VerifyError**  
  Exception raised when verification fails and the chosen option is to raise an exception.

- **VerifyWarning**  
  Warning issued during verification when the chosen option is to warn about issues.

### Verification Options

Verification can be controlled using the following options:

- `"ignore"`: Do not report or fix any errors.
- `"warn"`: Issue warnings for errors found.
- `"exception"`: Raise exceptions for errors found.
- `"fix"`: Attempt to fix fixable errors and raise exceptions for unfixable errors.
- `"silentfix"`: Attempt to fix fixable errors silently without reporting.
- Combinations such as `"fix+warn"`, `"silentfix+exception"`, etc., allow fine control over fixing and reporting behavior.

### The `_Verify` Class

This class provides shared methods for verification of FITS headers or related objects.

- **run_option(option, err_text, fix_text, fix, fixable)**  
  Executes verification according to the specified option. It can fix errors if possible and returns a tuple indicating whether the error was fixable and a message describing the result.

- **verify(option="warn")**  
  Verifies all values in the instance according to the specified option. It handles reporting or raising errors and warnings based on the option.

### The `_ErrList` Class

A specialized list class used to collect verification errors. It supports nested error messages with indentation to represent hierarchical verification steps.

- **iter_lines(filter=None, shift=0)**  
  Iterates over the error messages with optional filtering and indentation for nested errors.

Utilities and Helper Functions
------------------------------

Several utility functions and mixins assist in handling FITS headers and related file operations.

### NotifierMixin

A mixin class that allows objects to register listeners and notify them of changes. This is useful for internal communication between FITS header components or related objects.

- **_add_listener(listener)**: Register a listener with a weak reference.
- **_remove_listener(listener)**: Remove a registered listener.
- **_notify(notification, *args, **kwargs)**: Notify all listeners of a particular change.

### String Encoding and Decoding

- **encode_ascii(s)**  
  Encodes strings or numpy string arrays to ASCII bytes.

- **decode_ascii(s)**  
  Decodes ASCII bytes or numpy byte arrays to strings, replacing non-ASCII characters with '?' and issuing warnings if necessary.

### File-like Object Utilities

Functions to inspect and handle file-like objects commonly used when reading or writing FITS files.

- **isreadable(f)**  
  Returns `True` if the file-like object can be read from.

- **iswritable(f)**  
  Returns `True` if the file-like object can be written to.

- **isfile(f)**  
  Returns `True` if the object represents an OS-level file or a wrapper around one.

- **fileobj_name(f)**  
  Returns a human-readable name for a file-like object, falling back to the class name if no name attribute is found.

- **fileobj_closed(f)**  
  Returns `True` if the file-like object is closed or if the input is a string (assumed to be a pathname).

Additional Utilities
--------------------

- **first(iterable)**  
  Returns the first item from an iterable.

- **itersubclasses(cls)**  
  Generator that yields all subclasses of a given class in depth-first order.

- **ignore_sigint(func)**  
  Decorator that temporarily ignores SIGINT (KeyboardInterrupt) signals during the execution of the decorated function, warning the user if an interrupt is received and raising it after completion.

- **pairwise(iterable)**  
  Returns pairs of consecutive items from an iterable, e.g., `(s0, s1), (s1, s2), ...`.

Summary
-------

This module provides robust tools for verifying and managing FITS headers, ensuring compliance with FITS standards and facilitating error handling and correction. The verification system is flexible, allowing users to choose how strictly to enforce standards and how to handle errors. Utilities for string encoding, file handling, and event notification complement the core verification functionality, making this module a comprehensive foundation for FITS header manipulation and validation.
