Encoding Media
==============

The encoding media functionality in the ftrack API provides mechanisms to handle media encoding operations within an ftrack session. This includes creating, managing, and interacting with media encoding entities and their associated data.

Session and Media Encoding
--------------------------

The `Session` class represents an isolated session for interaction with an ftrack server. It manages authentication, caching, event handling, and entity lifecycle, including media encoding entities.

### Creating Media Encoding Entities

Media encoding entities can be created using the `Session.create()` method. This method requires the entity type (e.g., `'MediaEncoding'`) and an optional dictionary of initial data to populate the entity's attributes.

Example:

```python
media_encoding = session.create('MediaEncoding', data={
    'name': 'Example Encoding',
    'format': 'mp4',
    'resolution': '1920x1080'
})
```

The created entity is automatically merged into the session cache and can be manipulated or persisted as needed.

### Managing Media Encoding Entities

Entities created or retrieved within a session are tracked for changes. The session provides properties to inspect the state of entities:

- `session.created` — List of newly created entities.
- `session.modified` — List of locally modified entities.
- `session.deleted` — List of deleted entities.

These properties help manage the lifecycle of media encoding entities and ensure that changes are properly recorded and persisted.

### Operations and Persistence

The session records operations performed on entities, including media encoding entities, through the `recorded_operations` attribute. Operations can be controlled via:

- `session.operation_recording(record_operations)` — Context manager to temporarily enable or disable operation recording.
- `session.reset()` — Clears local state, including pending operations and cache, useful for resetting media encoding workflows.

### Event Hub Integration

The session integrates with an event hub (`session.event_hub`) that allows publishing and subscribing to events related to media encoding processes. This facilitates real-time updates and notifications within the ftrack ecosystem.

Authentication and Requests
---------------------------

The `SessionAuthentication` class attaches ftrack session authentication information to HTTP requests, ensuring secure communication with the ftrack server during media encoding operations.

Caching
-------

The session uses a layered caching mechanism to optimize performance when handling media encoding entities. A memory cache is always enforced at the top level, with optional additional caches configurable during session initialization.

Schema and Entity Types
-----------------------

The session loads and caches schema information to build entity type classes dynamically. This enables the creation and manipulation of media encoding entities according to the server's schema definitions.

Compatibility and Server Information
------------------------------------

The session verifies compatibility with the connected ftrack server, ensuring that media encoding features are supported and function correctly.

Closing and Resetting Sessions
------------------------------

Proper management of sessions is crucial for media encoding workflows:

- `session.close()` — Closes the session, clears caches, and disconnects event hubs.
- `session.reset()` — Resets the session state without closing, useful for restarting encoding operations cleanly.

Summary
-------

The ftrack API's session management provides a robust foundation for encoding media within the ftrack environment. It handles authentication, caching, event management, and entity lifecycle, enabling efficient and secure media encoding workflows integrated with the broader ftrack system.
