Working with User Security Roles
================================

Overview
--------

User security roles in ftrack define the permissions and access levels assigned to users within the system. Managing these roles effectively is crucial for maintaining a secure and organized environment.

This document provides guidance on how to work with user security roles using the ftrack API.

Accessing Security Roles
------------------------

Security roles are entities within the ftrack system and can be accessed and manipulated through the `Session` object. You can query, create, modify, and delete security roles similarly to other entities.

Example: Querying Security Roles

```python
roles = session.query('select id, name from SecurityRole').all()
for role in roles:
    print('Role ID: {}, Name: {}'.format(role['id'], role['name']))
```

Creating a Security Role
------------------------

To create a new security role, use the `create` method on the session, specifying the entity type as `'SecurityRole'` and providing the necessary data.

Example:

```python
new_role = session.create('SecurityRole', {
    'name': 'New Role Name',
    'description': 'Description of the new role',
    # Additional attributes as required
})
session.commit()
```

Modifying Security Roles
------------------------

Security roles can be modified by updating their attributes and committing the changes.

Example:

```python
role = session.query('select id, name from SecurityRole where name is "Old Role Name"').one()
role['name'] = 'Updated Role Name'
session.commit()
```

Assigning Roles to Users
------------------------

Users can be assigned security roles by modifying the user's `security_roles` attribute, which is typically a collection of roles.

Example:

```python
user = session.query('select id, username from User where username is "jdoe"').one()
role = session.query('select id, name from SecurityRole where name is "Editor"').one()

user['security_roles'].append(role)
session.commit()
```

Removing Roles from Users

```python
user['security_roles'].remove(role)
session.commit()
```

Best Practices
--------------

- Always verify the permissions associated with a security role before assigning it to users.
- Use descriptive names and descriptions for security roles to clarify their purpose.
- Regularly audit user roles to ensure compliance with organizational policies.
- Use transactions (`session.commit()`) to persist changes safely.

Notes
-----

- Changes to security roles and user assignments may affect access control immediately or after a short delay depending on server configuration.
- Ensure you have appropriate permissions to modify security roles and user assignments.
