Less Frequently Used FITS Data Structures
========================================

This section provides an overview of some of the less commonly encountered data structures and utilities used in handling FITS (Flexible Image Transport System) files within the Astropy library. These components support advanced verification, notification, and file handling mechanisms that ensure robust and flexible FITS file manipulation.

Verification Framework
----------------------

Astropy's FITS handling includes a comprehensive verification system to check the integrity and correctness of FITS data structures. This system is built around the following key classes and concepts:

- **VerifyError** and **VerifyWarning**: Custom exception and warning classes used to signal verification errors and warnings respectively.

- **_Verify**: A mixin class providing shared methods to perform verification on FITS objects. It supports multiple verification options such as ignoring errors, issuing warnings, raising exceptions, or attempting to fix fixable errors automatically.

- **_ErrList**: A specialized list class that holds verification errors in a nested structure, allowing hierarchical error reporting with indentation to reflect the structure of the FITS data.

Verification Options
~~~~~~~~~~~~~~~~~~~~

Verification can be controlled via several options, including:

- `"ignore"`: Do not report errors.
- `"warn"`: Issue warnings for errors.
- `"exception"`: Raise exceptions on errors.
- `"fix"`: Attempt to fix fixable errors and raise exceptions on unfixable ones.
- `"silentfix"`: Attempt to fix fixable errors silently without reporting.
- Combinations such as `"fix+warn"` or `"silentfix+exception"` allow fine-grained control over fixing and reporting behavior.

The verification system is designed to be extensible and to provide detailed feedback on the state of FITS data structures, facilitating debugging and data integrity assurance.

NotifierMixin: Change Notification System
----------------------------------------

The **NotifierMixin** class provides a mechanism for FITS objects to notify interested listeners about changes. This is particularly useful for keeping different parts of a FITS data structure synchronized or for triggering updates in user interfaces or processing pipelines.

Key features include:

- Registration of listeners via weak references to avoid memory leaks.
- Notification of listeners through dynamically dispatched update methods named `_update_<notification>`.
- Automatic removal of listeners when they are no longer referenced elsewhere.
- Exclusion of listeners from object serialization to prevent issues during pickling.

This mixin supports internal communication within the FITS handling framework, enabling responsive and maintainable code.

Utility Functions for FITS File Handling
----------------------------------------

Several utility functions assist in managing file-like objects and string encoding relevant to FITS files:

- **encode_ascii(s)** and **decode_ascii(s)**: Convert strings or arrays between ASCII-encoded bytes and Unicode strings, handling edge cases such as non-ASCII characters gracefully.

- **isreadable(f)** and **iswritable(f)**: Determine if a file-like object supports reading or writing, respectively, by inspecting attributes and modes.

- **isfile(f)**: Checks if an object represents a low-level OS file or a wrapper around one.

- **fileobj_name(f)**: Retrieves a human-readable name for a file-like object, useful for logging and error messages.

- **fileobj_closed(f)**: Checks if a file-like object is closed, including handling of various wrapper objects.

These utilities ensure that FITS file operations are performed safely and correctly across a variety of file-like objects and environments.

Additional Helpers
------------------

- **first(iterable)**: Returns the first item from any iterable, simplifying common iteration patterns.

- **itersubclasses(cls)**: Recursively yields all subclasses of a given class, useful for introspection and dynamic class handling.

- **ignore_sigint(func)**: A decorator that temporarily suppresses KeyboardInterrupt (SIGINT) signals during the execution of a function, ensuring critical operations complete without interruption.

- **pairwise(iterable)**: Provides pairs of consecutive items from an iterable, facilitating operations that require lookahead or comparison between adjacent elements.

Summary
-------

While these data structures and utilities may not be frequently used directly by most users, they form the backbone of Astropy's robust FITS file handling capabilities. Understanding their roles can be valuable for advanced users developing custom FITS extensions, debugging complex FITS files, or contributing to the Astropy codebase.
