Computational Performance
=========================

The multioutput estimators provided in this module, such as `MultiOutputRegressor` and `MultiOutputClassifier`, extend single-output estimators to handle multiple outputs by fitting one separate estimator per target variable. This design has important implications for computational performance, which users should consider when applying these meta-estimators.

Parallelization
--------------

Both `MultiOutputRegressor` and `MultiOutputClassifier` support parallel execution of fitting, prediction, and partial fitting across multiple output targets via the `n_jobs` parameter. This parameter controls the number of jobs to run in parallel:

- `n_jobs=None` (default) means 1 unless within a `joblib.parallel_backend` context.
- `n_jobs=-1` uses all available processors.
- Any positive integer specifies the exact number of jobs.

Parallelization can significantly reduce wall-clock time when individual estimators are computationally expensive. However, when the base estimators are very fast to train or predict, the overhead of parallelism may outweigh the benefits, potentially resulting in slower performance.

Memory Usage
------------

Since a separate estimator is cloned and trained for each output target, memory consumption scales linearly with the number of outputs. This can lead to increased memory usage compared to single-output estimators, especially for problems with a large number of targets.

Incremental Learning
--------------------

If the base estimator supports incremental learning via a `partial_fit` method, the multioutput estimators also expose a `partial_fit` method that fits each output estimator incrementally. This can be beneficial for large datasets or streaming data scenarios, allowing models to be updated without retraining from scratch.

Overhead Considerations
-----------------------

- **Cloning Overhead:** Each output estimator is cloned from the base estimator, which may add overhead during initialization.
- **Validation Overhead:** Input validation and metadata routing add some computational cost but enable flexible parameter passing and integration with scikit-learn’s ecosystem.
- **Routing Overhead:** When metadata routing is enabled (`enable_metadata_routing=True`), additional processing occurs to route parameters to the appropriate sub-estimators.

Best Practices
--------------

- Use parallelization (`n_jobs` > 1) when base estimators are computationally intensive and the number of outputs is sufficiently large.
- For small numbers of outputs or very fast base estimators, consider setting `n_jobs=1` to avoid parallel overhead.
- Monitor memory usage when working with many output targets.
- Utilize `partial_fit` if supported by the base estimator to handle large datasets incrementally.

Summary
-------

The multioutput meta-estimators provide a straightforward and flexible approach to multi-target regression and classification by fitting independent models per output. Their computational performance depends on the complexity of the base estimator, the number of outputs, and the parallelization strategy. Proper tuning of the `n_jobs` parameter and awareness of memory requirements can help optimize performance for specific use cases.
