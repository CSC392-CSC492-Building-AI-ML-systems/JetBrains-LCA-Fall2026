Miscellaneous Features of `astropy.io.fits`
============================================

This section documents various miscellaneous utilities and internal features used within the `astropy.io.fits` subpackage. These features provide support for verification, notification, file handling, and other helper functions that facilitate FITS file processing.

Verification Framework
----------------------

`astropy.io.fits` includes a verification framework to check the integrity and correctness of FITS data structures. This framework is centered around the `_Verify` class and related utilities.

- **VerifyError** and **VerifyWarning**  
  Custom exception and warning classes used to report verification errors and warnings.

- **VERIFY_OPTIONS**  
  A list of allowed verification modes, including options such as `"ignore"`, `"warn"`, `"exception"`, `"fix"`, `"silentfix"`, and combinations thereof (e.g., `"fix+warn"`).

- **_Verify Class**  
  Provides shared methods for verification of FITS objects. The `verify` method runs checks according to the specified option, which controls whether errors are ignored, warned, raised as exceptions, or automatically fixed if possible.  
  Verification messages are collected and reported accordingly, with support for hierarchical error reporting.

- **_ErrList Class**  
  A specialized list subclass used to store nested verification error messages. It supports indentation and hierarchical formatting of error messages to clearly present issues at different levels of the FITS data structure.

Notifier Mixin
--------------

The `NotifierMixin` class provides an internal mechanism for objects to register listeners and notify them of changes. This is used within `astropy.io.fits` to enable communication between related objects without exposing this machinery to end users.

- Listeners are registered with weak references to avoid memory leaks.
- Notifications are sent by calling listener methods named `_update_<notification>`.
- The mixin handles adding, removing, and notifying listeners.
- Listeners that do not implement the expected update method are silently ignored.
- The mixin excludes listeners from object pickling to avoid serializing ephemeral state.

Utility Functions
-----------------

Several utility functions assist with common tasks related to file handling, string encoding, and iteration:

- **first(iterable)**  
  Returns the first item from any iterable.

- **itersubclasses(cls)**  
  A generator that yields all subclasses of a given class in depth-first order.

- **ignore_sigint(func)**  
  A decorator that temporarily ignores `SIGINT` (Ctrl-C) signals during the execution of the decorated function, preventing interruption until the function completes.

- **pairwise(iterable)**  
  Returns pairs of consecutive items from an iterable. For Python versions prior to 3.10, a custom implementation is provided.

- **encode_ascii(s)** and **decode_ascii(s)**  
  Functions to encode strings or numpy string arrays to ASCII bytes and decode ASCII bytes back to strings, respectively. They handle arrays and issue warnings if non-ASCII characters are encountered.

File-like Object Utilities
--------------------------

Functions to inspect and interact with file-like objects, which are common in FITS file handling:

- **isreadable(f)**  
  Returns `True` if the file-like object supports reading.

- **iswritable(f)**  
  Returns `True` if the file-like object supports writing.

- **isfile(f)**  
  Returns `True` if the object represents a low-level OS file or a wrapper around one.

- **fileobj_name(f)**  
  Attempts to determine a meaningful name for a file-like object, falling back to the class name if no name attribute is found.

- **fileobj_closed(f)**  
  Returns `True` if the file-like object is closed or if the input is a string (assumed to be a filename).

These utilities help ensure robust and flexible handling of various file-like inputs and outputs within the FITS I/O system.

Summary
-------

The miscellaneous features documented here provide foundational support for error verification, event notification, and file handling within `astropy.io.fits`. While these components are primarily intended for internal use, they contribute significantly to the robustness, flexibility, and maintainability of the FITS file processing capabilities in Astropy.
