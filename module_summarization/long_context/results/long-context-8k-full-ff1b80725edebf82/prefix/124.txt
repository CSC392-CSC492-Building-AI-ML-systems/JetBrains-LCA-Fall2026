Header Interface Transition Guide
=================================

Overview
--------

This guide provides an overview of the transition to the new Header interface, highlighting key concepts, verification mechanisms, and utility functions that support robust and flexible handling of FITS headers within the Astropy framework.

Verification Framework
----------------------

The verification framework is designed to ensure the integrity and correctness of header data. It provides a structured approach to validating header contents, reporting issues, and optionally fixing fixable problems.

Key Components:

- **VerifyError** and **VerifyWarning**: Custom exception and warning classes used to signal verification errors and warnings respectively.

- **VERIFY_OPTIONS**: A list of supported verification modes, including options to ignore, warn, raise exceptions, fix issues silently or with notifications, and combinations thereof.

- **_Verify Class**: Implements shared verification methods, including the `verify` method which executes verification according to the specified option. It handles error reporting, fixing fixable errors, and raising exceptions or warnings as appropriate.

- **_ErrList Class**: A specialized list class for managing nested verification error messages. It supports hierarchical error reporting with indentation to reflect the structure of the header elements.

Notification and Listener Pattern
---------------------------------

The transition introduces a mixin class, **NotifierMixin**, which enables objects to register listeners that are notified upon changes. This pattern facilitates internal communication between components without exposing implementation details to end users.

Features:

- Register listeners with weak references to avoid memory leaks.

- Notify listeners of specific changes by invoking corresponding update methods dynamically.

- Automatic cleanup of listeners when they are no longer referenced elsewhere.

Utility Functions and Compatibility
-----------------------------------

Several utility functions and compatibility helpers support the new header interface:

- **first(iterable)**: Returns the first item from any iterable.

- **itersubclasses(cls)**: Recursively yields all subclasses of a given class in depth-first order.

- **ignore_sigint(func)**: Decorator to temporarily ignore SIGINT (Ctrl+C) signals during the execution of a function, ensuring critical operations complete uninterrupted.

- **pairwise(iterable)**: Provides pairs of consecutive items from an iterable, with compatibility for Python versions prior to 3.10.

- **encode_ascii(s)** and **decode_ascii(s)**: Functions to encode strings or arrays to ASCII bytes and decode ASCII bytes back to strings, handling non-ASCII characters gracefully with warnings.

File-like Object Utilities
--------------------------

The interface includes robust utilities to handle file-like objects, ensuring compatibility and correct behavior across different types of inputs:

- **isreadable(f)** and **iswritable(f)**: Determine if a file-like object supports reading or writing, respectively.

- **isfile(f)**: Checks if an object represents an OS-level file or a wrapper around one.

- **fileobj_name(f)**: Retrieves a meaningful name for a file-like object, falling back to class/type names if necessary.

- **fileobj_closed(f)**: Checks if a file-like object is closed, or treats strings as closed paths.

Transition Notes
----------------

- Verification options now support combined modes (e.g., `"fix+warn"`) to provide flexible control over error handling and fixing behavior.

- The notification system is intended for internal use to facilitate communication between header-related objects and should not be exposed directly to users.

- Utility functions ensure consistent behavior across Python versions and handle edge cases such as empty arrays or non-ASCII characters in headers.

- The verification error reporting uses zero-based indexing, consistent with Python conventions.

Conclusion
----------

The new Header interface and its supporting infrastructure provide a more robust, flexible, and maintainable framework for working with FITS headers. Users and developers are encouraged to familiarize themselves with the verification options and notification mechanisms to fully leverage the capabilities of the updated system.
