Verification Scheme for FITS Data
=================================

Overview
--------

The verification scheme provides a structured approach to validate FITS (Flexible Image Transport System) data integrity and correctness. It is designed to identify errors and inconsistencies within FITS files and offers configurable options to handle these issues, including warning the user, raising exceptions, or automatically fixing fixable errors.

Verification Classes and Exceptions
----------------------------------

- **VerifyError**  
  Exception class raised when verification encounters errors that cannot be ignored or fixed.

- **VerifyWarning**  
  Warning class used to notify users of verification issues that do not necessarily halt processing.

Verification Options
--------------------

Verification behavior is controlled via a set of predefined options that dictate how errors are reported and handled:

- `"ignore"`: Do not report or fix errors.
- `"warn"`: Issue warnings for errors.
- `"exception"`: Raise exceptions on errors.
- `"fix"`: Attempt to fix errors and raise exceptions for unfixable errors.
- `"silentfix"`: Attempt to fix errors silently without reporting, but raise exceptions for unfixable errors.
- Combinations such as `"fix+warn"`, `"fix+ignore"`, `"silentfix+exception"`, etc., allow fine-grained control over fixing and reporting behavior.

These options enable users to tailor verification to their needs, balancing strictness and automation.

Verification Process
--------------------

The verification process is encapsulated in the `_Verify` class, which provides shared methods for running verification checks:

- **run_option(option, err_text, fix_text, fix, fixable)**  
  Executes verification logic based on the selected option. If the error is fixable and the option allows fixing, the provided fix function is called. The method returns a tuple indicating whether the error was fixable and a descriptive message.

- **verify(option="warn")**  
  Performs verification on all relevant values within the instance. It processes errors according to the specified option, handling fixing, warning, ignoring, or raising exceptions as appropriate. The method supports complex option combinations to customize behavior.

Error Reporting Structure
-------------------------

Verification errors are managed using the `_ErrList` class, which maintains a nested list structure representing errors at various levels of the FITS data hierarchy. This structure allows for organized and indented reporting of errors, making it easier to understand the context and location of each issue.

- The `_ErrList` supports iteration over error messages with optional filtering and indentation.
- Errors can be grouped by elements (e.g., HDU index, header keyword) to provide hierarchical context.

Usage Example
-------------

To verify a FITS data object with warnings on errors and automatic fixing of fixable issues, one might call:

```python
fits_data.verify(option="fix+warn")
```

This will attempt to fix any fixable errors and issue warnings for all errors encountered.

Notes
-----

- Verification uses zero-based indexing when reporting locations within FITS files.
- The verification scheme is integrated with Astropy's warning and exception framework to provide consistent user feedback.
- The design allows for extensibility and integration with various FITS data structures and classes.

Summary
-------

The verification scheme offers a flexible and robust mechanism to ensure FITS data integrity. By providing configurable options for error handling and a structured error reporting system, it facilitates both automated correction and user awareness of data issues, supporting reliable FITS data processing workflows.
