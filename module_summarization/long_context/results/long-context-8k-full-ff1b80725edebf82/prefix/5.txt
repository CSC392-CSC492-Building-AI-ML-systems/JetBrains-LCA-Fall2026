Publishing Versions
===================

The ftrack API provides a robust mechanism for managing and publishing versions of entities within a session. This functionality is primarily handled through the `Session` class, which represents an isolated session for interaction with an ftrack server.

Session Overview
----------------

A `Session` encapsulates the connection to an ftrack server, managing authentication, caching, event handling, and entity lifecycle. It supports creating, modifying, and deleting entities, as well as recording operations and publishing events related to these changes.

Key Features Related to Publishing Versions
-------------------------------------------

- **Entity Creation and Modification**  
  Entities can be created using the `Session.create()` method, which initializes an entity of a specified type with optional data. Entities created or modified within a session are tracked locally until changes are persisted.

- **Operation Recording**  
  The session records operations performed on entities, allowing for batch processing and controlled publishing of changes. Operation recording can be temporarily enabled or disabled using the `operation_recording()` context manager.

- **Auto-Population of Attributes**  
  When enabled (default), accessing entity attributes automatically fetches missing data from the server, ensuring that published versions are consistent and complete.

- **Event Hub Integration**  
  The session integrates with an event hub (`Session.event_hub`) that facilitates publishing and subscribing to events, including those related to version publishing. The event hub can be auto-connected in the background or manually managed.

- **Caching**  
  The session uses a layered caching system to optimize performance and reduce redundant server requests. This cache also helps manage the state of entities before publishing.

Publishing Workflow
-------------------

1. **Create or Modify Entities**  
   Use `Session.create()` to create new entities or modify existing ones within the session context.

2. **Record Operations**  
   Changes to entities are recorded as operations. These can be reviewed or manipulated before publishing.

3. **Publish Changes**  
   Once ready, operations can be persisted to the server, effectively publishing the new or updated versions of entities.

4. **Event Notification**  
   Publishing triggers events via the event hub, notifying other components or systems of the changes.

Session Management for Publishing
---------------------------------

- **Closing a Session**  
  Use `Session.close()` to properly close the session, ensuring all connections are closed and caches cleared. Note that closing a session with pending operations that have not been persisted will log a warning.

- **Resetting a Session**  
  `Session.reset()` clears all pending operations and local cache, reconfiguring session aspects dependent on the cache. This is useful for discarding uncommitted changes and starting fresh.

- **Temporary Contexts**  
  The session provides context managers such as `auto_populating()` and `operation_recording()` to temporarily adjust behavior during publishing workflows.

Version State Inspection
------------------------

The session allows inspection of entities based on their state:

- `Session.created` — List of newly created entities not yet persisted.
- `Session.modified` — List of locally modified entities.
- `Session.deleted` — List of entities marked for deletion.

These properties help in managing and publishing versions by clearly identifying the entities that have changed within the session.

Server Compatibility and Reset
------------------------------

- The session checks server compatibility to ensure that the server version supports the API features required for publishing.

- Server-side resets can be performed using `Session.reset_remote()`, which supports various reset types as defined by the server. This can be used to revert or adjust published versions on the server.

Summary
-------

The ftrack API's session management provides comprehensive support for publishing versions of entities, including creation, modification, operation recording, event publishing, and cache management. By leveraging these features, users can effectively manage version lifecycles and ensure consistent synchronization with the ftrack server.
