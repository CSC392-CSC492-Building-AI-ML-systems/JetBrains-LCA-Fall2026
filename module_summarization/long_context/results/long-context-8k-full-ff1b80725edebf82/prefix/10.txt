Using metadata
==============

The `metadata` in the ftrack API context refers to the additional information and configuration that can be associated with entities and sessions to enhance interaction with the ftrack server.

Session Metadata
----------------

When creating a `Session` object to interact with an ftrack server, several metadata-related parameters and behaviors are important to understand:

- **Server URL (`server_url`)**  
  The URL of the ftrack server to connect to, including any port number. If not specified, it is retrieved from the environment variable `FTRACK_SERVER`.

- **API Key and User (`api_key`, `api_user`)**  
  Credentials used for authentication. If not provided explicitly, they are fetched from the environment variables `FTRACK_API_KEY` and `FTRACK_API_USER` respectively. The API key and user are attached to requests as metadata headers to authenticate and identify the user.

- **Auto Populate (`auto_populate`)**  
  A boolean flag indicating whether entity attributes should be automatically fetched from the server when accessed if not already present locally. This controls how metadata about entities is lazily loaded.

- **Plugin Paths (`plugin_paths`)**  
  Paths to search for plugins that can extend session functionality. These plugins may use or modify metadata related to events or entities.

- **Cache and Cache Key Maker (`cache`, `cache_key_maker`)**  
  The session uses a layered cache system to store entities and their metadata locally for performance. The cache key maker defines how keys for cached objects are generated.

- **Schema Cache Path (`schema_cache_path`)**  
  Path to a file where schema metadata is cached to improve performance. If not specified, a default cache directory or environment variable `FTRACK_API_SCHEMA_CACHE_PATH` is used.

- **Event Hub (`event_hub`)**  
  The session includes an event hub that manages event metadata and allows publishing and subscribing to events on the ftrack server.

Entity Metadata
---------------

Entities created or retrieved through the session carry metadata that describes their state and attributes:

- **Entity Types**  
  Entities are instances of classes dynamically built from schema metadata describing the entity types supported by the server.

- **Entity States**  
  Entities have states such as `CREATED`, `MODIFIED`, and `DELETED` which reflect their lifecycle and changes in metadata. These states can be inspected via the session properties:
  
  - `created` — List of newly created entities.
  - `modified` — List of locally modified entities.
  - `deleted` — List of deleted entities.

- **Operations Recording**  
  The session records operations performed on entities as metadata to allow for batching and committing changes to the server.

Working with Metadata
---------------------

- **Creating Entities**  
  Use the session's `create` method to instantiate new entities with initial metadata. The created entity is merged into the session cache.

- **Resetting Metadata**  
  The session supports resetting local and remote metadata states:
  
  - `reset()` clears local cached metadata and pending operations.
  - `reset_remote(reset_type, entity=None)` performs server-side resets on metadata for specified entities or types.

- **Auto Populating Context**  
  Temporarily control metadata fetching behavior using the `auto_populating` context manager to enable or disable automatic attribute population.

- **Operation Recording Context**  
  Temporarily enable or disable recording of operations that modify metadata using the `operation_recording` context manager.

Best Practices
--------------

- Always close sessions using `close()` to ensure metadata caches and connections are properly cleaned up.

- Use the session's event hub to listen for metadata changes and react to events in real-time.

- Leverage schema caching to improve performance when working with metadata-heavy operations.

- Be cautious when resetting sessions or entities to avoid losing unsaved metadata changes.

Summary
-------

Metadata in the ftrack API is a foundational aspect that enables rich interaction with the server, efficient caching, and event-driven workflows. Understanding how to manage and utilize metadata through sessions and entities is key to effective use of the API.
