Generate Documentation for Scan Plans
=====================================

This module provides a collection of scan plans designed for experimental control and data acquisition workflows. These plans facilitate systematic variation of one or more experimental parameters (motors, controllers, etc.) while collecting data from detectors. The plans support both absolute and relative positioning, linear and logarithmic spacing, and multi-dimensional scanning patterns.

Key Functions
-------------

count(detectors, num=1, delay=None, *, per_shot=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Take one or more readings from detectors.

- **detectors**: list of readable objects to collect data from.
- **num**: number of readings to take; if None, capture data until canceled.
- **delay**: time delay(s) between successive readings.
- **per_shot**: optional callable hook for customizing actions per reading.
- **md**: optional metadata dictionary.

list_scan(detectors, *args, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Scan over one or more variables in simultaneous steps (inner product).

- **detectors**: list of readable objects.
- **args**: pairs of (motor, list_of_positions) defining scan points.
- **per_step**: optional callable hook for customizing actions per step.
- **md**: optional metadata dictionary.

rel_list_scan(detectors, *args, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Scan over variables in steps relative to their current positions.

- Same parameters as `list_scan`.
- Positions are interpreted as relative offsets.

list_grid_scan(detectors, *args, snake_axes=False, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Scan over a mesh grid; each motor moves independently.

- **snake_axes**: controls snaking behavior of axes to optimize scan trajectory.
- Other parameters as in `list_scan`.

rel_list_grid_scan(detectors, *args, snake_axes=False, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Relative version of `list_grid_scan`, scanning relative to current motor positions.

_scan_1d(detectors, motor, start, stop, num, *, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Scan one variable in equally spaced steps between start and stop.

_rel_scan_1d(detectors, motor, start, stop, num, *, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Relative version of `_scan_1d`, scanning relative to current motor position.

log_scan(detectors, motor, start, stop, num, *, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Scan one variable in logarithmically spaced steps between start and stop.

rel_log_scan(detectors, motor, start, stop, num, *, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Relative version of `log_scan`, scanning relative to current motor position.

Common Parameters
-----------------
- **detectors**: List of readable objects (e.g., detectors) from which data is collected.
- **motor(s)**: Settable objects representing experimental parameters to be varied.
- **start, stop**: Numerical values defining scan range.
- **num**: Number of points or steps in the scan.
- **per_step / per_shot**: Optional callable hooks to customize behavior at each step or shot.
- **md**: Optional dictionary for metadata to be attached to the scan.

Metadata and Hints
------------------
Each plan generates and updates a metadata dictionary (`md`) that includes:

- Names of detectors and motors involved.
- Number of points and intervals.
- Plan arguments and plan name.
- Scan pattern information (e.g., linspace, logspace, inner or outer product).
- Hints for visualization or downstream processing, such as dimensions and fields.

Usage Notes
-----------
- Relative scans use decorators to reset and adjust motor positions relative to their current state.
- The `snake_axes` parameter in grid scans allows for optimized scanning trajectories by reversing direction on specified axes.
- The `per_step` and `per_shot` hooks enable users to inject custom behavior during scanning, such as additional data collection or conditional logic.
- The plans rely on external modules for cycling through scan points and managing execution flow (`plan_patterns`, `utils`, `preprocessors`, `plan_stubs`).
