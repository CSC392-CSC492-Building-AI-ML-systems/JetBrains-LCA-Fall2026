w_red Command
=============

Overview
--------

The `w_red` command applies the RED (Rate Estimation from Duration) scheme to estimate steady-state Weighted Ensemble (WE) fluxes from shorter trajectory data. This approach allows for improved rate constant estimation by correcting raw fluxes using event duration information.

The source data for the RED calculation is provided as a WESTPA "scheme," typically defined in the `west.cfg` configuration file. For example, if a scheme named "DEFAULT" is specified, `w_red` will estimate RED fluxes based on the data contained in the `assign.h5` and `direct.h5` files located in the `ANALYSIS/DEFAULT` directory.

Usage
-----

Run the `w_red` command in the environment where your WESTPA simulation data and configuration are accessible. The command reads parameters from the `west.cfg` file under the `[west.analysis.red]` section.

Configuration Parameters
------------------------

The following parameters must be specified in the `west.cfg` file for `w_red` to operate correctly:

- **scheme**: The name of the WESTPA scheme to analyze (e.g., "DEFAULT").
- **istate_label**: The label of the initial state for the rate calculation.
- **fstate_label**: The label of the final state for the rate calculation.
- **nstiter**: Number of steps per iteration (duration of each iteration).
- **nstrep**: Report interval (number of steps between reports).

Additionally, the kinetics evolution method must be set to `"cumulative"` in the `[west.analysis.kinetics]` section, as only cumulative averaging is supported for RED estimation at this time.

Functionality
-------------

The `w_red` command performs the following steps:

1. **Reads Configuration**: Extracts RED parameters and scheme information from `west.cfg`.

2. **Loads Data**: Opens the `direct.h5` and `assign.h5` files from the specified scheme directory under `ANALYSIS/`.

3. **Calculates Rates**: Uses the `RateCalculator` class to compute raw and RED-corrected rate constants over iterations. The RED correction is applied using the `DurationCorrector` class, which analyzes event durations and weights to compute a correction factor.

4. **Saves Results**: Attempts to save the RED flux evolution data to the `red_flux_evolution` dataset within the `direct.h5` file. If the dataset already exists, the user is prompted to overwrite or save the data as a separate `.npy` file.

Mathematical Background
-----------------------

The RED correction factor is computed based on the distribution of event durations and their weights. The correction factor \( C \) is given by:

\[
C = \frac{\theta}{\int_0^\theta \int_0^t \tilde{f}(\tau) \, d\tau \, dt}
\]

where:

- \(\theta\) is the maximum duration time observed (usually the simulation length).
- \(\tilde{f}(\tau)\) is a normalized histogram proportional to the weighted frequency of events with duration \(\tau\), corrected by the factor \(1/(\theta - \tau)\).

This correction accounts for the bias introduced by finite trajectory lengths in estimating steady-state fluxes.

Output
------

- The RED-corrected flux evolution is saved in the `red_flux_evolution` dataset inside the `direct.h5` file of the specified scheme directory.
- If the dataset exists and the user opts not to overwrite, the flux data is saved as a NumPy `.npy` file named `red_flux_evolution.npy` in the scheme directory.

Example
-------

Assuming your `west.cfg` contains the appropriate `[west.analysis.red]` section with the required parameters, simply run:

```
w_red
```

The command will read the configuration, perform the RED flux estimation, and save the results accordingly.

Notes
-----

- Only cumulative averaging for kinetics evolution is supported for RED estimation.
- The command requires that the initial and final states specified exist in the scheme's state labels.
- The RED scheme improves rate estimates from shorter trajectories by correcting for event duration biases.

For more detailed information on the RED method and its implementation, refer to the source code and associated WESTPA documentation.
