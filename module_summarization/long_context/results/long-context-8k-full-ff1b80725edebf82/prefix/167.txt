Library Conventions
===================

This library follows a set of conventions to ensure consistency, clarity, and usability across its modules and functions. This document summarizes the key conventions used throughout the library.

Module and File Structure
-------------------------

- Modules are organized by functionality, e.g., `dtime.py` for discrete time system manipulation, `optimal.py` for optimization-based control.
- Each module begins with a docstring summarizing its purpose and listing the main routines or classes it provides.
- Copyright and licensing information is included at the top of each file, along with author and date metadata.

Naming Conventions
------------------

- Function and variable names use lowercase with underscores (`snake_case`).
- Class names use CapitalizedWords (`CamelCase`).
- Constants and configuration keys use lowercase with dots separating namespaces, e.g., `'optimal.minimize_method'`.
- Private or internal variables and methods are prefixed with an underscore (`_`).

Documentation Style
-------------------

- Docstrings follow the NumPy/SciPy style, including sections for Parameters, Returns, Notes, and Examples.
- Parameters are clearly typed and described, including expected types, shapes, and value ranges.
- Return values specify the type and description.
- Notes provide additional context or references to related functions or methods.
- Examples illustrate typical usage with code snippets.
- Cross-references to classes and functions use Sphinx-style markup, e.g., :class:`StateSpace`, :func:`scipy.optimize.minimize`.

Function and Class Design
-------------------------

- Functions are designed to be modular and reusable, often wrapping or extending functionality from other libraries (e.g., SciPy).
- Classes encapsulate related data and behavior, with clear initialization parameters and methods.
- Default parameter values are centralized in configuration dictionaries or module-level variables.
- Error checking is performed early, with informative exceptions raised for invalid inputs.
- Logging is supported optionally via the standard Python `logging` module, controlled by parameters such as `log=True`.

Optimal Control Problem Conventions
-----------------------------------

- The `OptimalControlProblem` class encapsulates the definition of an optimal control problem, including system dynamics, cost functions, and constraints.
- Constraints are specified as lists of tuples containing constraint types (`LinearConstraint` or `NonlinearConstraint`), functions, and bounds.
- Constraints are applied at each time point along the trajectory and at the terminal time.
- Cost functions are separated into integral costs (evaluated along the trajectory) and terminal costs.
- Initial guesses for optimization inputs can be provided as arrays, supporting both time-varying and constant inputs.
- Optimization parameters such as solver methods and options are configurable via keyword arguments or global defaults.
- The class maintains internal state to cache computations and improve efficiency during optimization.
- Equality and inequality constraints are handled distinctly to improve solver performance and avoid warnings.

System Sampling Conventions
---------------------------

- Functions such as `sample_system` and `c2d` convert continuous-time systems to discrete-time representations.
- Input systems must be continuous-time; otherwise, a `ValueError` is raised.
- Sampling methods include zero-order hold (`'zoh'`), bilinear transform (`'bilinear'`), and generalized bilinear transform (`'gbt'`).
- Parameters such as sampling period (`Ts`), method, prewarp frequency, and weighting parameters are clearly documented.
- Returned systems maintain the same class type as the input (e.g., `StateSpace` or `TransferFunction`).
- Functions delegate to system methods (e.g., `StateSpace.sample`) for implementation details.

General Coding Practices
------------------------

- Imports are grouped and explicit, including relative imports for internal modules.
- The `__all__` variable is used to define the public API of modules.
- Code includes inline comments explaining non-obvious logic and design decisions.
- Performance considerations include caching results and minimizing redundant computations.
- Use of standard scientific Python libraries (`numpy`, `scipy`, `control`) is preferred for numerical operations and optimization.
- Exception handling is used to enforce correct usage and provide meaningful error messages.

Licensing and Attribution
-------------------------

- Each file includes a copyright notice and license terms.
- Authors and contributors are credited explicitly.
- Redistribution and use conditions are clearly stated.
- Disclaimer of warranties and liabilities is included.

By adhering to these conventions, the library ensures a consistent and maintainable codebase that is accessible to users and contributors alike.
