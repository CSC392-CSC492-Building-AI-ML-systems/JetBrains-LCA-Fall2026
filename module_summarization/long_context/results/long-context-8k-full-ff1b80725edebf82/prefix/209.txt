Analyzing a Collection of Text Documents
========================================

The `sklearn.feature_extraction.text` submodule provides utilities to transform a collection of text documents into numerical feature vectors suitable for machine learning algorithms. This process involves several key steps including decoding, preprocessing, tokenization, stop word filtering, and n-gram generation.

Overview
--------

Text analysis typically starts with raw text documents which need to be converted into a structured format. The submodule offers flexible tools to customize each step of this transformation pipeline.

Key Components
--------------

### Decoding

Input documents can be provided as filenames, file objects, byte strings, or unicode strings. The decoding step converts these inputs into unicode strings for further processing. For example, if the input is a filename, the file is read in binary mode and decoded using the specified encoding.

### Preprocessing

Preprocessing involves cleaning and normalizing the text before tokenization. Common preprocessing steps include:

- Lowercasing all characters.
- Stripping accents from characters, either by removing unicode accents or transliterating to ASCII.
- Removing HTML or XML tags using regular expressions.

The preprocessing function can be customized or replaced entirely.

### Tokenization

Tokenization splits the preprocessed text into tokens (words or characters). The submodule supports:

- Word tokenization using regular expressions.
- Character n-grams.
- Character n-grams within word boundaries (with padding).

Custom tokenizers can also be provided.

### Stop Words Filtering

Stop words are common words that are often removed to reduce noise in the data. The submodule supports built-in English stop words or user-provided lists. Stop words are filtered out after tokenization.

### N-grams Generation

N-grams are contiguous sequences of n tokens. The submodule supports generating:

- Word n-grams (e.g., unigrams, bigrams, trigrams).
- Character n-grams.
- Character n-grams within word boundaries.

The range of n-grams to generate can be specified.

Analyzing a Document
--------------------

The analysis pipeline can be summarized as follows:

1. **Decoding**: Convert input to unicode string.
2. **Preprocessing**: Apply lowercasing, accent stripping, and tag removal.
3. **Tokenization**: Split text into tokens.
4. **Stop Words Removal**: Filter out stop words.
5. **N-grams Generation**: Create n-grams from tokens.

This pipeline is encapsulated in the `_analyze` function, which chains these steps together. Users can customize or replace any step by providing their own functions.

Preprocessing Utilities
-----------------------

- `strip_accents_unicode(s)`: Removes accents from unicode characters by decomposing them and removing combining characters.
- `strip_accents_ascii(s)`: Transliterates accented unicode characters to ASCII equivalents.
- `strip_tags(s)`: Removes HTML/XML tags using a regular expression.

Vectorizer Mixin
----------------

The `_VectorizerMixin` class provides common functionality for text vectorizers, including:

- Decoding input documents.
- Building preprocessors and tokenizers.
- Managing stop words.
- Generating word and character n-grams.
- Validating vocabulary and n-gram ranges.
- Warning about unused parameters when custom analyzers or tokenizers are used.

Analyzers
---------

The analyzer is a callable that processes input text and returns a sequence of tokens or n-grams. The submodule supports several analyzer types:

- `"word"`: Tokenizes text into words, applies stop word filtering, and generates word n-grams.
- `"char"`: Generates character n-grams from the entire text.
- `"char_wb"`: Generates character n-grams only within word boundaries, padding edges with spaces.
- Custom callable analyzers can replace the entire pipeline.

Stop Words Consistency
----------------------

The vectorizer checks for consistency between the stop words list and the preprocessing/tokenization steps. If tokenizing the stop words produces tokens not in the stop words list, a warning is issued.

Vocabulary Validation
---------------------

The vocabulary maps tokens to feature indices. The vectorizer validates the vocabulary to ensure:

- No duplicate tokens.
- Indices are unique and contiguous.
- Vocabulary is not empty.

If no vocabulary is provided, it is built during fitting.

Summary
-------

The `sklearn.feature_extraction.text` submodule provides a flexible and extensible framework for analyzing collections of text documents. By customizing preprocessing, tokenization, stop word filtering, and n-gram generation, users can tailor the feature extraction process to their specific needs, enabling effective text-based machine learning.
