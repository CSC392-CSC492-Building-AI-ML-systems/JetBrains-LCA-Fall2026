Table Data
==========

Overview
--------

The Table Data module provides classes and utilities for handling and verifying table-like data structures, particularly in the context of FITS (Flexible Image Transport System) files. It includes mechanisms for verification of data integrity, notification of changes, and utilities for working with file-like objects and string encoding.

Verification
------------

Verification is a key feature provided to ensure the integrity and correctness of table data. The verification framework supports multiple options for handling errors and warnings during the verification process.

### Verification Options

The following verification options are supported:

- **ignore**: Do not report or fix errors.
- **warn**: Issue warnings for errors.
- **exception**: Raise exceptions for errors.
- **fix**: Attempt to fix errors and raise exceptions for unfixable errors.
- **silentfix**: Attempt to fix errors silently without reporting.
- **fix+ignore**, **fix+warn**, **fix+exception**: Combination of fixing errors and reporting them with ignore, warn, or exception behavior.
- **silentfix+ignore**, **silentfix+warn**, **silentfix+exception**: Combination of silent fixing and reporting.

### Classes for Verification

- **VerifyError**: Exception class raised when verification fails with errors.
- **VerifyWarning**: Warning class issued during verification warnings.
- **_Verify**: Base class providing shared methods for verification. It includes the `verify` method which runs verification according to the specified option and handles error reporting and fixing.

### Error List

- **_ErrList**: A specialized list class for managing nested verification errors. It supports hierarchical error messages with indentation to represent different levels of verification.

Notification System
-------------------

The module includes a mixin class to support notification of changes to objects, allowing listeners to be registered and notified when changes occur.

- **NotifierMixin**: Provides internal methods to add and remove listeners and notify them of changes. Listeners are held with weak references to avoid memory leaks. Notifications are sent by calling listener methods named `_update_<notification>`.

Utilities
---------

Several utility functions are provided to assist with common tasks related to table data handling:

- **first(iterable)**: Returns the first item from an iterable.
- **itersubclasses(cls)**: Generator that yields all subclasses of a given class in depth-first order.
- **ignore_sigint(func)**: Decorator to ignore SIGINT (KeyboardInterrupt) signals during the execution of a function.
- **pairwise(iterable)**: Returns pairs of consecutive items from an iterable.
- **encode_ascii(s)**: Encodes strings or string arrays to ASCII bytes.
- **decode_ascii(s)**: Decodes ASCII bytes or byte arrays to strings, with warnings for non-ASCII characters.
- **isreadable(f)**: Checks if a file-like object is readable.
- **iswritable(f)**: Checks if a file-like object is writable.
- **isfile(f)**: Determines if an object represents an OS-level file.
- **fileobj_name(f)**: Returns a human-readable name for a file-like object.
- **fileobj_closed(f)**: Checks if a file-like object is closed.

These utilities facilitate robust handling of file operations, string encoding, and class introspection within the table data context.

Usage Example
-------------

```python
from astropy.io.fits.table import _Verify

class MyTable(_Verify):
    def _verify(self, option):
        errs = _ErrList(unit="Row")
        # Perform verification checks here
        # Append errors or warnings to errs
        return errs

table = MyTable()
table.verify(option="warn")
```

This example demonstrates how to subclass the verification base class and implement custom verification logic for table data.

Notes
-----

- Verification messages use zero-based indexing.
- The notification system is intended for internal use and uses weak references to manage listeners.
- The module is designed to work seamlessly with FITS files and the Astropy ecosystem.
