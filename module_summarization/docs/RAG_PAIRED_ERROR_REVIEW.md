# Module summarization paired error review

Reviewed 12 tasks from the completed 2K prefix and 2K BM25 run. The sample includes four large BM25 losses, four large wins, two broad directory overviews, and two no-match fallbacks. This is a diagnostic sample selected after scoring. It does not estimate error rates for all 216 tasks.

For each task, compare the reference from the fingerprinted test split with the two saved predictions and their exact supplied code. All 24 contexts in the review matched their traced offsets in the dataset, and their reconstructed user prompts matched the saved digests. The [run directory](../benchmark_results/paired-full-gpt41-mini-15055eac3076fca7/) has the predictions and traces under `prefix/` and `bm25/` using the task ID as the filename stem.

## What to test next

- Carry the narrow API cases and broad overviews into development smoke tests. Check whether 8K direct context makes missing definitions visible, then check whether the summary actually uses them. A larger budget can help with code outside the first 2K, while cases such as SQLAlchemy and OpenPype entities also expose limits in the supplied code pool.
- Use the session and LDAP cases to exercise agent follow-up reads. Check that the agent follows references to public APIs and uses deprecation guidance when it is present.
- After the required long-context and agent arms are running, test one retrieval change. A first candidate is wider chunks, 800 instead of 400 with 50-token overlap and the same 2K total budget, to test whether nearby definitions and usage survive together. Treat this as a hypothesis. Check retained evidence and judge scores on repositories excluded from tuning.
