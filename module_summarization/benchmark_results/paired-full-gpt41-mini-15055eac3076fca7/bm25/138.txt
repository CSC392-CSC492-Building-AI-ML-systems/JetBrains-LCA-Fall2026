Array Best Practices
====================

This document outlines best practices for working with arrays, particularly in the context of chunked and distributed array computations. Following these guidelines will help you write efficient, maintainable, and scalable array-processing code.

Chunking and Chunk Size
-----------------------

- **Balance Chunk Sizes:** When working with chunked arrays, aim to balance chunk sizes to avoid significant disparities. Balanced chunks improve parallelism and reduce overhead. If chunk size balancing is not possible with the given chunks, consider increasing the chunk size.

- **Choosing Chunk Sizes:** Use heuristics or functions to determine optimal chunk sizes based on the median chunk length and a small epsilon range to explore alternatives. Select the chunk size that minimizes the difference between the largest and smallest chunks.

- **Align Chunk Sizes with Storage:** For best performance when storing arrays, align the chunk size of your array with the block size of your storage target. This alignment reduces overhead and improves I/O efficiency.

Reduction Operations
--------------------

- **Use Built-in Reductions:** Utilize built-in reduction functions such as `np.sum`, `np.prod`, `np.min`, and `np.max` for coarsening or aggregating data. These functions are optimized and can be combined with chunking strategies for efficient computation.

- **Coarsening Arrays:** When coarsening arrays (reducing resolution by aggregating over blocks), provide a dictionary mapping each axis to its coarsening factor. For example, coarsening a 2D array with `{0: 2, 1: 3}` reduces the first axis by a factor of 2 and the second by 3.

- **Example of Coarsening:**

  ```python
  import numpy as np

  x = np.arange(24).reshape((4, 6))
  # Coarsen by summing over blocks of size 2 along axis 0 and 3 along axis 1
  coarsened = coarsen(np.sum, x, {0: 2, 1: 3})
  # Result:
  # array([[ 0,  3],
  #        [12, 15]])
  ```

Top-k Selection
---------------

- **Extracting Top-k Elements:** Use specialized functions like `topk` to extract the k largest or smallest elements along a given axis. If `k` is positive, the function returns the k largest elements sorted from largest to smallest; if negative, it returns the -k smallest elements sorted from smallest to largest.

- **Performance Considerations:** These operations perform best when `k` is much smaller than the chunk size. Results are returned in a single chunk along the specified axis.

- **Parameters:**
  - `a`: Input array.
  - `k`: Number of elements to select.
  - `axis`: Axis along which to perform the selection.
  - `split_every`: Controls the tree reduction depth to optimize performance when `k` is large relative to chunk size.

- **Indices of Top-k Elements:** Use `argtopk` to obtain the indices of the top-k elements with similar performance considerations.

Storing Arrays
--------------

- **Chunk-wise Storage:** When storing Dask arrays into array-like objects that support NumPy-style indexing, store values chunk by chunk. This approach avoids loading the entire array into memory.

- **Locking:** Use locking mechanisms (`lock=True` or a threading.Lock) to prevent concurrent writes from corrupting data when storing arrays in parallel.

- **Matching Sources and Targets:** Ensure that the collection of source arrays matches the collection of target arrays in structure and chunking.

General Recommendations
-----------------------

- **Avoid Large Chunks:** Extremely large chunks can lead to memory bottlenecks and reduce parallelism. Conversely, very small chunks increase overhead. Find a balance based on your workload and hardware.

- **Benchmarking:** Performance depends on workload, scheduler, and hardware. Benchmark your specific use case to find optimal parameters.

- **Use High-Level APIs:** Utilize high-level functions and abstractions provided by libraries to manage chunking, reductions, and storage efficiently.

- **Memory Management:** When possible, prefer operations that do not require loading the entire dataset into memory. Use chunked computations and lazy evaluation.

Summary
-------

Efficient array processing requires careful consideration of chunk sizes, reduction strategies, and storage mechanisms. By balancing chunk sizes, leveraging optimized reduction functions, and storing data chunk-wise with appropriate locking, you can achieve scalable and performant array computations. Always tailor these practices to your specific workload and environment through benchmarking and profiling.
