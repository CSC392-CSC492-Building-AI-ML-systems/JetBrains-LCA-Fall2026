Executing Notebooks
===================

The `ExecutePreprocessor` class provides functionality to execute all the code cells in a Jupyter notebook and update their outputs accordingly. This is useful for running notebooks programmatically, ensuring that all code cells are executed and their outputs are captured.

Overview
--------

The execution functionality is implemented as a preprocessor that can be integrated into notebook conversion workflows. It inherits from both `Preprocessor` and `NotebookClient` to combine traitlets configuration and notebook execution capabilities.

Key Components
--------------

- **ExecutePreprocessor**  
  This class executes all the cells in a notebook. It can be configured with various options such as the kernel name to use for execution. Upon execution, the notebook's code cells are run in order, and their outputs are updated with the results.

- **executenb**  
  A deprecated function that was previously used to execute notebooks. It now issues a `FutureWarning` and delegates execution to the `nbclient.execute` function. Users are encouraged to import and use `nbclient.execute` directly.

Usage
-----

To execute a notebook programmatically, instantiate the `ExecutePreprocessor` and call its `preprocess` method with a notebook object:

```python
import nbformat
from nbconvert.preprocessors import ExecutePreprocessor

# Load the notebook
with open("notebook.ipynb") as f:
    nb = nbformat.read(f, as_version=4)

# Create the preprocessor and execute the notebook
ep = ExecutePreprocessor(timeout=600, kernel_name='python3')
output_nb, resources = ep.preprocess(nb, resources={})

# The output_nb now contains the executed notebook with updated outputs
```

Features
--------

- Executes all code cells in the notebook sequentially.
- Supports specifying the kernel to use for execution.
- Updates the notebook metadata, including populating `language_info` if missing.
- Handles execution errors by raising exceptions such as `CellExecutionError`.
- Can be subclassed to customize cell execution behavior by overriding methods like `preprocess_cell`.

Example Tests
-------------

The module includes tests demonstrating typical usage scenarios:

- Executing a simple notebook and verifying outputs remain consistent.
- Executing notebooks with mixed markdown and code cells.
- Ensuring that language information is populated in notebook metadata after execution.
- Customizing cell execution by subclassing `ExecutePreprocessor` and overriding `preprocess_cell`.

Notes
-----

- The `executenb` function is deprecated and will be removed in future releases. Use `nbclient.execute` instead.
- The execution process normalizes outputs to handle variations such as memory addresses in output text.
- Execution errors during cell processing raise `CellExecutionError` exceptions, allowing for error handling in workflows.
