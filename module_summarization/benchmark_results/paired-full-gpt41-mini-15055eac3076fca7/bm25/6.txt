Working with User Security Roles
================================

Overview
--------

User security roles in ftrack define the permissions and access levels assigned to users within the system. Managing these roles effectively is crucial for maintaining secure and organized project workflows.

Assigning Security Roles to Users
---------------------------------

Users can be assigned one or more security roles that determine their capabilities and access rights. These roles control what actions a user can perform and which resources they can access.

Sending User Invitations
------------------------

The API provides methods to send invitations to users, which can be used to onboard new users with appropriate security roles:

- **send_user_invite(user)**  
  Sends an invitation to a single user. The *user* parameter should be an instance of a User.

- **send_user_invites(users)**  
  Sends invitations to multiple users. The *users* parameter should be a list of User instances.

Example usage:

```python
session.send_user_invite(user)
session.send_user_invites([user1, user2])
```

Error Handling
--------------

When sending user invitations, the server may reject the request if the action is not supported by the server version. In such cases, a `ServerCompatibilityError` is raised with a message indicating that the server version does not support the `send_user_invite` action and suggesting to update the server.

Authentication
--------------

Interactions with the ftrack server require authentication using an API key and user identifier. The `SessionAuthentication` class attaches the necessary authentication headers to HTTP requests:

- `ftrack-api-key`: The API key for authentication.
- `ftrack-user`: The user identifier.

Example:

```python
auth = SessionAuthentication(api_key='your_api_key', api_user='your_username')
```

Session Management
------------------

The `Session` class represents an isolated session for interacting with the ftrack server. It manages authentication, caching, plugin loading, and event handling.

When creating a session, you can specify:

- `api_key` and `api_user` for authentication.
- `cache` and `cache_key_maker` for caching session data.
- `plugin_paths` to specify locations of event plugins.
- Other parameters to customize session behavior.

Security Best Practices
-----------------------

- Always ensure that users are assigned the minimum necessary security roles to perform their tasks.
- Regularly review and update user roles to reflect changes in responsibilities.
- Use server-side validation and error handling to prevent unauthorized actions.
- Keep the ftrack server updated to support the latest security features and API actions.

Environment Variables
---------------------

The API user can be specified via the `api_user` parameter or through environment variables such as `FTRACK_API_USER`. If not provided, the system attempts to determine the current user via standard Python methods.

Notes
-----

- The session automatically manages a layered cache with a memory cache at the top level to optimize performance.
- Attempting to send user invitations on unsupported server versions will result in informative errors to guide corrective actions.

For detailed information on managing users and security roles, refer to the ftrack API documentation and server administration guides.
