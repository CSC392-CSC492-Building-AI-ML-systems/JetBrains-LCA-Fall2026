Pipelines and Composite Estimators
==================================

The `sklearn.pipeline` module provides utilities to build composite estimators, which are chains of transforms and estimators. These composite estimators facilitate the creation of complex machine learning workflows by sequentially applying a list of transforms and a final estimator.

Pipeline
--------

A `Pipeline` chains multiple estimators into one. Intermediate steps must be transformers (i.e., implement `fit` and `transform` methods), and the final step can be any estimator (implementing `fit` and optionally `predict` or `transform`). This allows for encapsulating the entire workflow into a single object that can be treated as a standard estimator.

### Key Features

- Each step is a tuple `(name, estimator)` where `name` is a string identifier and `estimator` is an object implementing `fit` and `transform` or `fit` and `predict`.
- Parameters of steps can be accessed and set using the `'__'` (double underscore) syntax. For example, to set the parameter `n_components` of a step named `pca`, use `pca__n_components`.
- Steps can be replaced or removed by setting the corresponding parameter to another estimator, `'passthrough'`, or `None`.
- Supports caching of fitted transformers to avoid recomputing them during repeated calls.
- Integrates seamlessly with scikit-learn's model selection utilities such as `GridSearchCV`.

### Example Usage

```python
from sklearn.pipeline import Pipeline
from sklearn.decomposition import PCA
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ('pca', PCA(n_components=2)),
    ('clf', LogisticRegression())
])

pipe.fit(X_train, y_train)
pipe.predict(X_test)
```

### Parameters

- `steps` : list of tuples  
  List of `(name, transform)` tuples (implementing `fit`/`transform`) chained in sequential order. The last transform must be an estimator.
- `memory` : str or joblib.Memory object, default=None  
  Used to cache the fitted transformers of the pipeline. The last step is never cached.
- `verbose` : bool, default=False  
  If True, the time elapsed while fitting each step will be printed as it is completed.

FeatureUnion and Composite Estimators
-------------------------------------

Composite estimators can also be created by combining multiple transformers in parallel using `FeatureUnion`. This allows for applying different transformations to the data and concatenating their outputs.

### FeatureUnion

`FeatureUnion` takes a list of transformer objects and applies them in parallel to the input data, concatenating their outputs. This is useful for combining features generated by different feature extraction mechanisms.

### Example Usage

```python
from sklearn.pipeline import FeatureUnion
from sklearn.decomposition import PCA, TruncatedSVD

union = FeatureUnion([
    ('pca', PCA(n_components=2)),
    ('svd', TruncatedSVD(n_components=2))
])

X_transformed = union.fit_transform(X)
```

Parameters of transformers inside a `FeatureUnion` can also be set using the `'__'` syntax, e.g., `union.set_params(pca__n_components=1)`.

make_pipeline Utility
---------------------

The `make_pipeline` function is a convenience function to create a `Pipeline` without explicitly naming the steps. It automatically assigns names to the steps based on the lowercase of their estimator types.

```python
from sklearn.pipeline import make_pipeline
from sklearn.decomposition import PCA
from sklearn.linear_model import LogisticRegression

pipe = make_pipeline(PCA(n_components=2), LogisticRegression())
```

This is equivalent to:

```python
pipe = Pipeline([
    ('pca', PCA(n_components=2)),
    ('logisticregression', LogisticRegression())
])
```

Summary
-------

Pipelines and composite estimators in scikit-learn provide a powerful and flexible way to build complex machine learning workflows by chaining and combining multiple transformers and estimators. They support parameter tuning, caching, and integration with model selection tools, enabling clean and maintainable code for machine learning tasks.

For more detailed information, refer to the :ref:`User Guide <pipeline>` and the examples provided in the scikit-learn documentation.
