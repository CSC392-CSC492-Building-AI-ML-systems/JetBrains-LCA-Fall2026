Generate Documentation for Code
===============================

This documentation provides an overview of several scanning and tuning plans used in experimental control, particularly for motorized stages and detectors. These plans facilitate complex motion patterns such as spirals and adaptive tuning steps, with metadata support for enhanced traceability and integration.

Spiral and Pattern Scanning Plans
---------------------------------

The code includes implementations of various spiral scanning patterns, which are commonly used in scientific experiments to cover an area systematically.

### Spiral Square Pattern

- **Parameters:**
  - `x_motor`, `y_motor`: Motors controlling the X and Y axes.
  - `x_center`, `y_center`: Center coordinates for the spiral.
  - `x_range`, `y_range`: Range of motion in X and Y directions.
  - `x_num`, `y_num`: Number of steps in X and Y directions.
  - `md` (optional): Metadata dictionary.

- **Description:**
  Generates a square spiral pattern by moving the motors in a sequence that covers a square area. The metadata includes a dictionary of plan arguments with motor references replaced by their string representations for clarity.

- **See Also:**
  - `bluesky.plans.relative_spiral_square`
  - `bluesky.plans.spiral`
  - `bluesky.plans.relative_spiral`
  - `bluesky.plans.spiral_fermat`
  - `bluesky.plans.relative_spiral_fermat`

### Spiral Pattern

- **Parameters:**
  - `x_motor`, `y_motor`: Motors controlling the X and Y axes.
  - `x_start`, `y_start`: Starting coordinates.
  - `x_range`, `y_range`: Range of motion.
  - `dr`, `nth`, `dr_y`: Parameters controlling spiral density and step size.
  - `tilt` (float, optional): Tilt angle in radians, default is 0.0.
  - `per_step` (callable, optional): Hook for customizing the action of the inner loop per step.
  - `md` (optional): Metadata dictionary.

- **Description:**
  Creates a spiral scanning pattern starting from specified coordinates. The `tilt` parameter allows rotation of the spiral, and `per_step` enables customization of actions during each step. Metadata includes plan arguments with motor references converted to string representations.

- **See Also:**
  - `bluesky.plans.rel_spiral`
  - `bluesky.plans.spiral_fermat`
  - `bluesky.plans.rel_spiral_fermat`

Adaptive Tuning Plan: Tweak
---------------------------

- **Parameters:**
  - `detector`: The detector device used to measure the data field.
  - `target_field`: The data field whose output is the focus of the adaptive tuning.
  - `motor`: The motor device to be adjusted.
  - `step`: Initial suggestion for step size.
  - `md` (optional): Metadata dictionary.

- **Description:**
  Implements an adaptive tuning step that adjusts a motor based on feedback from a detector's data field. The plan constructs metadata including detector and motor names, plan arguments with string representations of devices, and hints for plotting dimensions if available.

Metadata Handling
-----------------

All plans include optional `md` parameters to accept metadata dictionaries. Before including motor and detector objects in metadata, these are converted to their string representations (`repr`) to ensure serializability and clarity in logs.

The metadata dictionaries typically contain:

- `plan_name`: Name of the plan.
- `plan_args`: Dictionary of arguments used in the plan, with device references as strings.
- `detectors`: List of detector names.
- `motors`: List of motor names.
- `hints`: Optional hints for visualization or further processing.
- `extents`: Spatial extents covered by the scan (where applicable).

Decorators and Execution Context
--------------------------------

Some plans use decorators such as:

- `@bpp.reset_positions_decorator`: Resets motor positions after the plan completes.
- `@bpp.relative_set_decorator`: Sets motors relative to their current positions.

These decorators help manage motor states and ensure safe and predictable execution of scanning patterns.

Summary
-------

The provided code defines a suite of scanning and tuning plans with comprehensive metadata support, enabling detailed tracking and reproducibility of experimental procedures. The plans cover a range of spiral scanning patterns and adaptive motor tuning, with flexibility for customization and integration into larger experimental workflows.
