File Objects
============

File objects represent HDF5 files and provide the primary interface for accessing and manipulating the contents of these files. They serve as the root container for all other HDF5 objects such as groups, datasets, datatypes, and attributes.

Key Features
------------

- **File Format Versions**  
  File objects support multiple HDF5 format versions to ensure compatibility and leverage new features. The versioning is controlled by the `H5F_libver_t` enumeration, which includes:  
  - `H5F_LIBVER_EARLIEST` (value 0): Use the earliest possible format for storing objects.  
  - `H5F_LIBVER_V18` (value 1)  
  - `H5F_LIBVER_V110` (value 2)  
  - `H5F_LIBVER_V112` (value 3) (available in HDF5 versions >= 1.11.4)  
  - `H5F_LIBVER_LATEST`: Use the latest possible format available for storing objects.  

- **Object Identification**  
  File objects are identified by the type ID `H5I_FILE` (value 1) within the HDF5 library's internal object management system. This distinguishes them from other object types such as groups (`H5I_GROUP`), datasets (`H5I_DATASET`), datatypes (`H5I_DATATYPE`), dataspaces (`H5I_DATASPACE`), and attributes (`H5I_ATTR`).

- **Hierarchical Structure Navigation**  
  File objects allow hierarchical navigation and manipulation of contained objects. For example, groups and datasets can be accessed or created by specifying their path within the file. Paths containing slashes (`'/'`) are split into components to traverse or create intermediate groups as needed.

- **Virtual Dataset Mapping**  
  File objects can work with virtual datasets (VDS) through the `VDSmap` utility, which encodes filenames and dataset names appropriately to map sources into a virtual space.

- **Thread Safety and Configuration**  
  File objects respect configuration options such as `track_order` to maintain the order of object creation, which can be controlled via the HDF5 configuration interface.

Usage Notes
-----------

- When specifying object names within a file, paths can be given as strings with components separated by slashes (`'/'`). The file object will parse these paths, navigate existing groups, or create new groups as necessary to reach the target object.

- The file format version can be selected to balance compatibility and feature availability, with `H5F_LIBVER_LATEST` providing access to the newest features supported by the HDF5 library version in use.

- File objects are the entry point for all HDF5 operations and provide handles to lower-level APIs such as the virtual file layer (VFL) and property lists.

Summary of Relevant Constants and Types
---------------------------------------

- **H5F_libver_t Enumeration**  
  Defines file format versions for storing objects:
  - `H5F_LIBVER_EARLIEST` = 0  
  - `H5F_LIBVER_V18` = 1  
  - `H5F_LIBVER_V110` = 2  
  - `H5F_LIBVER_V112` = 3 (if HDF5 version >= 1.11.4)  
  - `H5F_LIBVER_LATEST` (integer constant for latest format)

- **H5I_type_t Enumeration**  
  Defines object type identifiers:
  - `H5I_UNINIT` = -2 (uninitialized type)  
  - `H5I_BADID` = -1 (invalid type)  
  - `H5I_FILE` = 1 (File objects)  
  - `H5I_GROUP` (Group objects)  
  - `H5I_DATATYPE` (Datatype objects)  
  - `H5I_DATASPACE` (Dataspace objects)  
  - `H5I_DATASET` (Dataset objects)  
  - `H5I_ATTR` (Attribute objects)  
  - `H5I_VFL` (Virtual file layer)  
  - `H5I_VOL` (Virtual Object Layer)

This documentation provides an overview of File objects within the HDF5 ecosystem, highlighting their role, versioning capabilities, and integration with other HDF5 components.
