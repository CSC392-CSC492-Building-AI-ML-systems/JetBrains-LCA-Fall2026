Publishing Versions
===================

The publishing system in the API supports versioning to ensure that objects stored in the cache and published through the event hub are properly managed and tracked.

Key Generation
--------------

Keys for objects being stored in the *cache* are generated using the `rack_api.cache.KeyMaker` interface. If no specific key maker is provided, a default implementation, :class:`~ftrack_api.cache.StringKeyMaker`, will be used. This ensures consistent and reliable key generation for all cached objects.

Event Hub Connection
--------------------

Publishing and subscribing to events is managed through an embedded event hub. The event hub can be connected automatically or manually depending on the configuration:

- If *auto_connect_event_hub* is set to True, the embedded event hub will automatically connect to the event server. This allows publishing and subscribing to **non-local** events seamlessly.
- If *auto_connect_event_hub* is False, only **local** event publishing and subscribing will be possible until the event hub is manually connected using the method :meth:`EventHub.connect <ftrack_api.event.hub.EventHub.connect>`.

.. note::

    The event hub connection is performed in a background thread to improve session startup time. If a registered plugin requires a connected event hub, it should explicitly check the event hub connection status. Note that subscribing to events does *not* require the event hub to be connected.

Schema Caching
--------------

To improve performance, schema caching can be enabled by specifying a folder path via the *schema_cache_path* parameter. If this parameter is not set, the environment variable :envvar:`FTRACK_API_SCHEMA_CACHE_PATH` will be used to determine the cache storage location.

This caching mechanism helps reduce overhead when publishing versions by reusing schema information efficiently.
