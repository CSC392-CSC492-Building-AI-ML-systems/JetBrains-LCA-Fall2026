Logging Module
==============

Overview
--------
This module provides an advanced logging framework built on top of Python's standard `logging` library. It extends the default logging capabilities by supporting structured data logging, custom log levels, and flexible output handlers including console, file, and syslog with asynchronous support.

Key Features
------------
- **Structured Data Logging**: Enables attaching structured data to log messages via the `struct_data` parameter.
- **Custom Log Level**: Defines a new log level `NOTICE` (level 25) for informational messages that are visible in non-verbose modes.
- **Multiple Handlers**: Supports console, rotating file, and syslog handlers with configurable formats and rotation policies.
- **AsyncIO Integration**: Uses asynchronous handlers for syslog to integrate smoothly with asyncio event loops.
- **RFC5424 Syslog Formatting**: Implements RFC5424-compliant syslog message formatting with microsecond precision timestamps.
- **Container Awareness**: Detects if running inside a container environment to adjust logging behavior accordingly.

Constants
---------
- `LOG_NOTICE` (int): Custom log level with value 25, representing informational messages that are less verbose than `INFO`.
- `_NAME_TO_LEVEL` (dict): Mapping of string log level names to their corresponding numeric values, including aliases.

Classes
-------

Logging
-------
A class responsible for initializing and configuring the root logger and its handlers based on application configuration.

- **Initialization**: Sets up console, file, and syslog handlers if enabled in the configuration.
- **ConsoleHandler**: Outputs logs to the console with optional color formatting.
- **FileHandler**: Supports log file output with rotation based on time intervals (seconds, minutes, hours, days).
- **SyslogHandler**: Sends logs to a syslog server or Unix socket asynchronously.
- **Log Rotation**: Supports periodic log rotation using a timer mechanism.
- **Configuration**: Reads settings from a `Config` object, including formats, date formats, log levels, and rotation policies.

_StructuredDataLogger (subclass of logging.Logger)_
---------------------------------------------------
Extends the standard Python `Logger` class to support an additional `struct_data` parameter in logging methods.

- **Usage**: Allows calls like `logger.info("Message", struct_data={'key': 'value'})`.
- **Implementation**: Overrides the `_log` method to inject structured data into the `extra` dictionary passed to the logging framework.

StructuredDataFormatter (subclass of logging.Formatter)
-------------------------------------------------------
A logging formatter that renders log messages including structured data in a consistent format.

- **Structured Data Rendering**: Formats the structured data dictionary into the log output.
- **Timestamp**: Uses GMT time for timestamps.
- **Format String**: Customizable format string supporting structured data identifiers.

SyslogRFC5424microFormatter (subclass of StructuredDataFormatter)
-----------------------------------------------------------------
Implements syslog message formatting compliant with RFC5424 with microsecond precision timestamps.

- **Format**: Produces syslog messages with priority, timestamp, hostname, application name, process ID, logger name, level, structured data, and message.
- **Empty Structured Data**: Uses `-` to indicate absence of structured data as per RFC5424.

Usage Example
-------------
```python
import logging
from log_module import Logging

app = ...  # Your application context
logging_system = Logging(app)

logger = logging.getLogger(__name__)
logger.info("Application started", struct_data={"event": "start", "status": "success"})
```

Log Levels
----------
- `DEBUG` (10): Detailed information, typically of interest only when diagnosing problems.
- `INFO` (20): Confirmation that things are working as expected.
- `NOTICE` (25): Informational messages visible in non-verbose mode, less severe than warnings.
- `WARNING` (30): An indication that something unexpected happened, or indicative of some problem.
- `ERROR` (40): Due to a more serious problem, the software has not been able to perform some function.
- `CRITICAL` (50): A serious error, indicating that the program itself may be unable to continue running.

Configuration
-------------
The logging behavior is controlled via a `Config` object with sections such as:

- `logging:console`: Settings for console output (format, date format, color usage).
- `logging:file`: Settings for file output including file path, format, date format, and rotation policy (`rotate_every`).
- `logging:syslog`: Settings for syslog output including enable flag and address.

Notes
-----
- The module automatically sets the logger class to `_StructuredDataLogger` to support structured data.
- Log rotation intervals can be specified using a number followed by a unit (`s` for seconds, `M` for minutes, `H` for hours, `d` for days).
- The syslog handler supports both Unix socket and TCP connections.
- The module detects if running inside a container to adjust logging behavior accordingly.

Dependencies
------------
- Python standard libraries: `logging`, `logging.handlers`, `asyncio`, `socket`, `os`, `sys`, `time`, `re`, `traceback`, `urllib.parse`
- Custom modules: `Config` (configuration management), `Timer` (for scheduling log rotation), `running_in_container` (environment detection)

This module provides a robust and extensible logging framework suitable for complex applications requiring structured logging and integration with syslog and asynchronous event loops.
