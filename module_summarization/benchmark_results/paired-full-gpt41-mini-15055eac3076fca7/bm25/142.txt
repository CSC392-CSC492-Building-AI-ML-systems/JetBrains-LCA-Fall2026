dask.delayed
=============

The `dask.delayed` interface provides a simple way to parallelize and build task graphs from normal Python functions and objects. It allows you to delay the execution of functions and computations, constructing a lazy task graph that can be executed later.

Basic Usage
-----------

You can apply `delayed` to functions to delay their execution:

```python
from dask import delayed

def inc(x):
    return x + 1

# Normal function call
inc(10)
# 11

# Delayed function call
x = delayed(inc, pure=True)(10)
type(x) == Delayed
# True
x.compute()
# 11
```

You can also use `delayed` as a decorator:

```python
@delayed(pure=True)
def add(a, b):
    return a + b

add(1, 2).compute()
# 3
```

Purity and Key Naming
---------------------

The `delayed` interface accepts an optional keyword argument `pure`. If `pure=True` (default), calls to the delayed function with the same arguments will produce the same key, enabling caching and reuse of results. If `pure=False`, each call produces a unique key, useful for non-pure functions such as those involving randomness or time.

```python
from dask import delayed
from operator import mul

# Pure delayed function calls produce the same key
print(mul(1, 2).key == mul(1, 2).key)
# True

# Non-pure delayed function calls produce different keys
with dask.config.set(delayed_pure=False):
    print(mul(1, 2).key == mul(1, 2).key)
# False
```

You can explicitly specify the key name of a delayed call using the `dask_key_name` keyword argument:

```python
add(1, 2)
# Delayed('add-3dce7c56edd1ac2614add714086e950f')

add(1, 2, dask_key_name='three')
# Delayed('three')
```

Note that objects with the same key name are assumed to have the same result. If you set key names explicitly, ensure they are unique for different results.

```python
add(1, 2, dask_key_name='three')
add(2, 1, dask_key_name='three')
add(2, 2, dask_key_name='four')
```

Delayed Objects and Collections
-------------------------------

`delayed` can also be applied to objects to make operations on them lazy:

```python
a = delayed([1, 2, 3])
isinstance(a, Delayed)
# True
```

Normalization and Task Graph Extraction
---------------------------------------

The function `to_task_dask(expr)` normalizes a Python object and merges all sub-graphs by:

- Replacing `Delayed` objects with their keys
- Converting literals to scheduler-compatible forms
- Extracting Dask graphs from all enclosed values

Parameters
~~~~~~~~~~

- `expr` : object  
  The object to be normalized. This function handles `Delayed` objects and most built-in Python types.

Returns
~~~~~~~

- `task` : normalized task to be run  
- `dask` : a merged Dask graph that forms the DAG for this task

Example:

```python
import dask
a = delayed(1, 'a')
b = delayed(2, 'b')
task, dask_graph = to_task_dask([a, b, 3])
task
# ['a', 'b', 3]
dict(dask_graph)
# {'a': 1, 'b': 2}
```

Similarly, `unpack_collections(expr)` normalizes Python objects and merges all sub-graphs, replacing `Delayed` objects with their keys and extracting Dask graphs from enclosed values. It returns a normalized task and a tuple of collections.

Finalizing Collections
----------------------

The `finalize(collection)` function creates a delayed object that represents the post-computation step of a Dask collection. It constructs a new task graph layer that applies the collection's postcompute function to its keys.

Example:

```python
finalized = finalize(collection)
```

This returns a `Delayed` object representing the finalized computation.

Notes
-----

- The `delayed` interface is a powerful tool for building complex task graphs from simple Python code.
- Use the `pure` argument to control key generation and caching behavior.
- Use `dask_key_name` to explicitly name tasks when needed.
- Functions like `to_task_dask` and `unpack_collections` help in normalizing and extracting task graphs from nested delayed objects and collections.
- The `finalize` function helps in wrapping up computations on Dask collections into delayed objects.

For more advanced usage and examples, refer to the Dask documentation and API reference.
