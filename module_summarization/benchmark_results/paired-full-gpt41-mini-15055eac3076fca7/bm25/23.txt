w_fork Command
==============

Overview
--------
The `w_fork` command is used to prepare a new weighted ensemble simulation from an existing one at a specified iteration. It generates a new HDF5 file representing the new simulation. This command is particularly useful for branching or restarting simulations from a particular point in a previous simulation.

Description
-----------
`w_fork` creates a new weighted ensemble simulation by copying the state of an existing simulation at a given iteration. The new simulation inherits the target states and basis states from the original simulation. The command produces a new HDF5 file containing the new simulation data, including a mapping from the old simulation's segments to the new simulation's initial states.

When using executable propagation, it is the user's responsibility to prepare the new simulation directory appropriately. This includes making the old simulation's restart data from the specified iteration available as the new simulation's initial state data. To assist with this, `w_fork` creates a mapping of old simulation segments to new simulation initial states, which is saved both in the new HDF5 file and as a flat text file.

Usage
-----
```
w_fork [OPTIONS]
```

Options
-------
- `-i`, `--input`  
  Specify the input HDF5 file from which to create the new simulation. If not provided, the input file is read from the configuration.

- `-o`, `--output`  
  Specify the output HDF5 file to write the new simulation data.

- `-n`, `--niter`  
  The iteration number at which to fork the simulation. This is the iteration from the original simulation that will be used as the starting point for the new simulation.

- `--no-headers`  
  When writing the initial state mapping file, suppress the inclusion of header lines.

- Additional options may be provided via the WESTPA runtime configuration system.

Output
------
- A new HDF5 file representing the forked simulation, containing the initial states and simulation metadata.

- A text file mapping old simulation segments to new simulation initial states. This file includes columns for:
  - Old simulation iteration number (`n_iter`)
  - Old simulation segment ID (`seg_id`)
  - New simulation initial state ID

Example
-------
To fork a simulation at iteration 50 from an existing simulation file `sim_old.h5` and write the new simulation to `sim_new.h5`:

```
w_fork -i sim_old.h5 -o sim_new.h5 -n 50
```

This will create `sim_new.h5` and a mapping file that relates segments from iteration 50 of the old simulation to initial states in the new simulation.

Notes
-----
- The user must ensure that the restart data from the old simulation at the specified iteration is available and correctly linked for the new simulation if executable propagation is used.

- Target states and basis states are copied from the original simulation to maintain consistency.

- The mapping file generated by `w_fork` aids in managing the relationship between old and new simulations, especially for setting up restart directories and initial state data.

Logging
-------
`w_fork` uses the `logging` module to provide informational and error messages during execution. The logger is named `w_fork`.
