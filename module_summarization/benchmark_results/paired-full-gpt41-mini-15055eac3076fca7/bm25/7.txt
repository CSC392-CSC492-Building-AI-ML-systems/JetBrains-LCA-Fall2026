Using Lists
===========

This section provides an overview of how lists are used and manipulated within the codebase, particularly focusing on handling collections of components, invitees, and entities.

Working with Component Lists
----------------------------

The code distinguishes between two types of components when processing lists: standard components and container components. Container components are identified by the presence of a `'members'` key.

Example:
- Standard components are processed separately from container components to optimize queries.
- The method `get_component_availabilities(components, locations=None)` returns availability information for a list of components.
- The method `get_component_availability(component, locations=None)` returns availability for a single component by internally calling `get_component_availabilities`.

Availability data is typically returned as a list of dictionaries or a dictionary mapping location IDs to percentage availability values.

Handling Invitee Lists
----------------------

Invitees to review sessions are managed as lists of `ReviewSessionInvitee` objects.

- `send_review_session_invite(invitee)` sends an invite to a single invitee.
- `send_review_session_invites(invitees)` sends invites to multiple invitees at once.

**Note:** All invitees must be committed before sending invites.

Entity State Lists
------------------

The code provides properties to retrieve lists of entities based on their state:

- `created`: Returns a list of newly created entities.
- `modified`: Returns a list of locally modified entities.
- `deleted`: Returns a list of deleted entities.

These lists are generated by inspecting the states of entities in the local cache and filtering accordingly.

Example usage:

```python
created_entities = session.created
modified_entities = session.modified
deleted_entities = session.deleted
```

Additional List Operations
--------------------------

- Filtering entities based on their modification state is done using `itertools.izip` to pair entities with their states.
- Lists of operations can be constructed dynamically, for example when preparing to send invites to multiple invitees.

Summary
-------

Lists are a fundamental data structure used throughout the code to manage collections of components, invitees, and entities. Proper handling and filtering of these lists enable efficient querying, state management, and batch operations.
