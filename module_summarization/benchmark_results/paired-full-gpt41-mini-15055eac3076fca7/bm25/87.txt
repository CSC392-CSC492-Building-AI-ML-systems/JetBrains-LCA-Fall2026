Generate Documentation for This Module
======================================

Overview
--------
This module provides functionality to run database migrations that have not yet been applied. It supports running migrations for a specific application or all applications, running up to a specified migration ID, and options to fake the migration or preview the SQL queries without executing them.

Functions
---------

run_migrations(app_name: str = "all", migration_id: str = "all", fake: bool = False, preview: bool = False)
----------------------------------------------------------------------------------------------------------
Runs any migrations which haven't been run yet.

Parameters:
- **app_name** (str):  
  The name of the app to migrate. Specify `"all"` to run migrations for all apps.

- **migration_id** (str):  
  Migrations will be run up to and including this migration ID.  
  - Specify `"all"` to run all migrations.  
  - Specify `"1"` to run only the next migration.

- **fake** (bool):  
  If set to `True`, records the migrations as having been run without actually executing them.

- **preview** (bool):  
  If set to `True`, does not run the migrations but prints the SQL queries that would be executed.

Behavior:
- Determines which migrations have not yet been run.
- Selects a subset of migrations to run based on the `migration_id` parameter.
- Prints the number of migrations to be run.
- Executes each migration in the subset, respecting the `fake` and `preview` options.
- If any migration fails, the process exits with a non-zero status code.

Usage Example
-------------
```python
await run_migrations(app_name="my_app", migration_id="all", fake=False, preview=False)
```

This will run all pending migrations for the application named `"my_app"`.

Exit Codes
----------
- Exits with status code `1` if any migration fails to run successfully.

Notes
-----
- The module prints informative messages to standard output and error streams.
- The `fake` option is useful for marking migrations as applied without making changes to the database.
- The `preview` option allows reviewing the SQL commands before applying them.

This module is intended to be used in asynchronous contexts and requires awaiting the `run_migrations` function.
