Metadata Routing API
====================

The Metadata Routing API provides a flexible mechanism to handle metadata requests and routing within objects, enabling structured and dynamic access to metadata properties. This API is primarily composed of two key classes: `MetadataRequest` and `MetadataRouter`, along with utility functions and method mappings to facilitate metadata extraction and routing.

Overview
--------

The routing mechanism allows objects to specify how metadata should be requested and routed through nested or composite structures. This is particularly useful in complex objects where metadata needs to be aggregated or delegated to child components.

Key Components
--------------

MetadataRequest
^^^^^^^^^^^^^^^

A `MetadataRequest` instance encapsulates a request for metadata properties. It represents the metadata that an object wants to expose or retrieve.

- **Creating Requests**: Objects can generate metadata requests by implementing a method that returns a `MetadataRequest` instance.
- **Accessing Requests**: The method `get_metadata_routing()` returns the routing information encapsulated in a `MetadataRequest`.
- **Usage**: This class is used to specify which metadata properties are requested and how they should be routed.

MetadataRouter
^^^^^^^^^^^^^^

The `MetadataRouter` class stores and manages metadata routing information for router objects. It maintains a mapping between child object names and their corresponding routing information.

- **Routing Information**: Stored as a dictionary mapping object names to `RouteMappingPair` instances, which include a `MethodMapping` and routing info (either a `MetadataRequest` or another `MetadataRouter`).
- **Initialization**: Created with an `owner` parameter indicating the name of the object to which the routing requests belong.
- **Adding Routes**: The `add()` method allows adding named objects along with their method mappings, specifying how metadata requests should be routed to child objects.
- **Representation**: Supports string and repr representations for debugging and inspection.

MethodMapping
^^^^^^^^^^^^^

`MethodMapping` defines the mapping between child and parent methods for metadata extraction. It can be created from strings or other specifications to define how method calls are routed.

Utility Functions
-----------------

`get_routing_for_object(obj=None)`
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

This function extracts a `MetadataRequest` or `MetadataRouter` instance from the given object.

- If the object already is a `MetadataRequest` or `MetadataRouter`, a copy is returned.
- If the object provides a `get_metadata_routing()` method, the output of that method is copied and returned.
- Otherwise, an empty `MetadataRequest` is returned.

This ensures that the routing information can be safely manipulated without affecting the original object.

Usage Example
-------------

Objects implementing metadata routing typically provide methods such as:

- `get_metadata_routing()`: Returns the routing information as a `MetadataRequest`.
- `get_requested_data_properties()`: Returns requested data properties encapsulated in a `MetadataRequest`.

Routers can add child objects and their method mappings using:

```python
router.add(method_mapping="some_method_mapping", child_obj=some_object)
```

This setup allows metadata requests to be propagated and handled appropriately across complex object hierarchies.

Version Information
-------------------

The Metadata Routing API was introduced in version 1.3.
