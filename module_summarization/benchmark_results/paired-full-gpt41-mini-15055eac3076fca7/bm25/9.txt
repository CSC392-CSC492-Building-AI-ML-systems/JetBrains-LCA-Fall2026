Using Timers
============

The ftrack API provides support for using timers to measure and manage time intervals within your applications. Timers can be useful for profiling code execution, scheduling tasks, or managing timeouts.

Basic Usage
-----------

To use timers, you typically create a timer instance and start it before the code section you want to measure. After the code executes, you stop the timer and retrieve the elapsed time.

Example:

.. code-block:: python

    import time
    from ftrack_api import Timer

    timer = Timer()
    timer.start()

    # Code to measure
    time.sleep(2)

    timer.stop()
    print('Elapsed time:', timer.elapsed)

Timer Features
--------------

- **Start and Stop**: You can start and stop the timer multiple times. The elapsed time accumulates across starts and stops.
- **Elapsed Time**: The timer provides the elapsed time in seconds as a floating-point number.
- **Context Manager Support**: Timers can be used as context managers to automatically start and stop timing a block of code.

Using Timer as a Context Manager
-------------------------------

You can use the timer in a `with` statement to automatically measure the duration of a code block:

.. code-block:: python

    from ftrack_api import Timer

    with Timer() as timer:
        # Code to measure
        do_something()

    print('Elapsed time:', timer.elapsed)

Advanced Usage
--------------

Timers can be integrated with the ftrack event system or logging to profile operations or monitor performance in your applications.

Consider using timers to:

- Profile plugin execution times.
- Measure API request durations.
- Schedule periodic tasks or timeouts.

Notes
-----

- Timers are lightweight and designed to have minimal impact on performance.
- Use timers to gain insights into your application's behavior and optimize accordingly.

For more detailed information and examples, refer to the ftrack API documentation and source code related to timers.
