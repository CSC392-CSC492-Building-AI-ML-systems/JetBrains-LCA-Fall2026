Using Review Sessions
=====================

Overview
--------

Review sessions provide a collaborative environment where participants can be invited to review and provide feedback on media or other assets. This functionality allows sending invitations to specific users or groups, managing review locations, and handling media components associated with the review process.

Sending Review Session Invites
------------------------------

You can send invitations to review sessions using the following methods:

- **send_review_session_invite(invitee)**  
  Sends an invite to a single review session participant.

  - *invitee*: An instance of `ReviewSessionInvitee`.  
  - **Note:** The invitee must be committed before sending the invite.

- **send_review_session_invites(invitees)**  
  Sends invites to multiple review session participants.

  - *invitees*: A list of `ReviewSessionInvitee` instances.  
  - **Note:** All invitees must be committed before sending the invites.

These methods internally prepare the necessary operations and communicate with the server to dispatch the invitations. If the server does not support the `send_review_session_invite` action, a `ServerCompatibilityError` will be raised, indicating that the server version needs to be updated.

Review Locations
----------------

Review sessions utilize specific locations to manage media components and resources. A special location named `'ftrack.review'` with a predefined identifier is used to store review-related assets.

When adding components to a review session, the system can automatically select an appropriate location:

- If the component name matches known review-specific names such as `'ftrackreview-mp4'`, `'ftrackreview-webm'`, or `'ftrackreview-image'`, the component is added to the `'ftrack.review'` location to maintain backward compatibility.
- Otherwise, a suitable location is picked automatically.

Component Management
--------------------

Components associated with review sessions can be created and registered with additional data and optionally assigned to specific locations.

- *data*: A dictionary containing additional attributes for the component.
- *location*: Specifies where to add the component. The default `'auto'` setting attempts to select a suitable location automatically. Setting this to `None` will prevent adding the component to any location.

When registering components, a session commit may be automatically issued to finalize the changes.

Additional Notes
----------------

- The system uses the `clique` library to parse file sequences when handling media components. For single files, size and file type metadata are automatically determined if not provided.
- Failed entity creations are handled carefully to avoid leaving inconsistent states in the session or cache.
- The review session functionality depends on server capabilities; ensure your server version supports the required actions for smooth operation.

See Also
--------

- `Clique documentation <http://clique.readthedocs.org>`_ for details on file sequence parsing and handling.

This documentation provides an overview of using review sessions, sending invites, managing review locations, and handling media components within the review workflow.
