Examples and Usage
==================

ManyToManyField
---------------

The `ManyToManyField` represents a many-to-many relationship between this model and another model.

**Parameters:**

- `model_name` (str):  
  The name of the related model in the format `'{app}.{model}'`. This parameter is required.

- `through` (Optional[str]):  
  The database table that represents the through table. This is optional and the default value is normally safe.

- `forward_key` (Optional[str]):  
  The forward lookup key on the through table. Optional, with a normally safe default.

- `backward_key` (str):  
  The backward lookup key on the through table. Optional, with a normally safe default.

- `related_name` (str):  
  The attribute name on the related model to reverse resolve the many-to-many relationship.

**Usage:**

```python
field = ManyToManyField(
    model_name='app.Model',
    through='app_through_table',
    forward_key='forward_id',
    backward_key='backward_id',
    related_name='related_models'
)
```

See the :ref:`many_to_many` section for more detailed usage information.


ForeignKeyField
---------------

The `ForeignKeyField` represents a foreign key relationship to another model.

**Parameters:**

- `model_name` (str):  
  The name of the related model in the format `'{app}.{model}'`. This parameter is required.

- `related_name` (Optional[str] or Literal[False]):  
  The attribute name on the related model to reverse resolve the foreign key. Optional.

- `on_delete` (str):  
  Defines the behavior when the related model is deleted. Possible values include:

  - `field.CASCADE`:  
    Indicates that the model should be cascade deleted if the related model gets deleted.

**Usage:**

```python
field = ForeignKeyField(
    model_name='app.Model',
    related_name='related_field',
    on_delete=field.CASCADE
)
```

See the :ref:`foreign_key` section for more detailed usage information.


Field Description
-----------------

Fields can be described and introspected using a dictionary representation.

By default, when `serializable=True` (the default), the description dictionary contains:

```python
{
    "name":         str,    # Field name
    "field_type":   str,    # Field type
    "db_column":    str,    # Name of DB column (optional, only for pk/data fields)
    "raw_field":    str,    # Name of raw field of the Foreign Key
    "description":  str,    # Description of the field (nullable)
    "docstring":    str,    # Field docstring (nullable)
}
```

When `serializable=False`, some fields are not coerced to valid JSON types and the dictionary contains:

```python
{
    "field_type":   Field,  # The Field class used
    "python_type":  Type,   # The actual Python type
    "default":      ...,    # The default value as native type OR a callable
}
```

This allows for detailed introspection of fields, including their types, defaults, and documentation.
