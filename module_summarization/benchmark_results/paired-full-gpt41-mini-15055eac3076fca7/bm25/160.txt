Compatibility Policy
====================

The `Generator` class and the new random number generation API in NumPy do **not** provide a version compatibility guarantee. This means that as improvements and better algorithms are developed, the underlying bit streams and random sequences produced by the generators may change between NumPy releases.

Key points regarding compatibility:

- The `Generator` class is designed to provide improved random number generation capabilities and exposes a variety of methods for generating random numbers from many probability distributions.
- The internal bit streams produced by the `BitGenerator` instances used by `Generator` may change as algorithms evolve, and thus the output sequences are not guaranteed to be reproducible across different NumPy versions.
- Users requiring reproducibility should be aware that the random sequences generated by the new API may differ between versions, even when using the same seed.
- The legacy random number generation functions (such as `rand`, `randn`, `ranf`, `random_integers`, `random_sample`, `randint`, and `seed`) have been removed or deprecated in the new API. These legacy functions had different compatibility and reproducibility characteristics.
- The `set_state` and `get_state` methods exist primarily for backward compatibility and advanced use cases. They allow manual manipulation of the internal state of the bit generators but should be used with caution.
- For most users, working with the distributions and generators provided by the new API does not require manual state management.

In summary, while the new random generation API offers enhanced functionality and improved algorithms, it does so without guaranteeing backward or forward compatibility of the generated random sequences. Users should design their applications accordingly and avoid relying on exact reproducibility of random sequences across NumPy versions.
