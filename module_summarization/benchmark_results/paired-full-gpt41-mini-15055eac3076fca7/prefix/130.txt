Less Frequently Used FITS Data Structures
=========================================

This section provides an overview of some of the less commonly encountered data structures in FITS (Flexible Image Transport System) files, along with notes on their verification and handling within the Astropy FITS module.

Verification Framework
----------------------

Astropy's FITS module includes a robust verification framework designed to check the integrity and correctness of FITS data structures. This framework supports multiple verification options to control how errors and warnings are handled, including ignoring issues, issuing warnings, raising exceptions, or attempting automatic fixes.

### Verification Options

The verification process can be customized using the following options:

- **ignore**: Do not report any verification issues.
- **warn**: Issue warnings for verification problems.
- **exception**: Raise exceptions on verification errors.
- **fix**: Attempt to fix fixable errors and raise exceptions for unfixable ones.
- **silentfix**: Attempt to fix fixable errors silently without reporting.
- Combinations such as **fix+warn**, **fix+ignore**, **silentfix+exception**, etc., allow fine-grained control over fixing and reporting behavior.

### Verification Process

The verification is performed by calling the `verify` method on FITS data structure instances. This method evaluates the data according to the selected option and reports or fixes errors accordingly. The process distinguishes between fixable and unfixable errors, applying fixes where possible and reporting issues based on the chosen verification option.

Error Reporting and Handling
----------------------------

Verification errors are collected in a nested list structure that reflects the hierarchical nature of FITS data components. This structure allows detailed reporting of errors at various levels, such as headers, data units, and extensions.

- Errors are represented as tuples indicating whether they are fixable and the associated message.
- The reporting mechanism supports indentation and formatting to clearly present nested error information.
- Depending on the verification option, errors may be ignored, warned about, or raised as exceptions.

Exception and Warning Classes
-----------------------------

- **VerifyError**: Exception class raised when verification encounters errors that cannot be ignored or fixed.
- **VerifyWarning**: Warning class used to issue warnings during verification without interrupting execution.

Usage Notes
-----------

- The verification framework is integral to ensuring FITS file compliance and data integrity.
- Users can select verification options that best suit their workflow, balancing strictness and convenience.
- Automatic fixing is available for certain classes of errors, but some issues require manual intervention.
- The framework uses zero-based indexing when reporting errors, consistent with Python conventions.

Summary
-------

While the core FITS data structures such as primary HDUs and image extensions are commonly used and well-supported, Astropy also provides mechanisms to handle and verify less frequently used or more complex FITS structures. The verification framework is a key tool in managing these data structures, helping users maintain FITS file validity and reliability.
