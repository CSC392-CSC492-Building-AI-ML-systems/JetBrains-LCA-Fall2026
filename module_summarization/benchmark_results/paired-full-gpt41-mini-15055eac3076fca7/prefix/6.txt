Working with User Security Roles
================================

Overview
--------

User security roles in ftrack define the permissions and access levels assigned to users within the system. Managing these roles effectively is crucial for maintaining a secure and organized environment, ensuring that users have appropriate access to projects, tasks, and other resources.

Understanding Security Roles
----------------------------

A security role in ftrack encapsulates a set of permissions that govern what actions a user can perform and what data they can access. Roles can be assigned to individual users or groups, allowing for flexible and scalable permission management.

Common security roles include:

- **Administrator**: Full access to all system features and settings.
- **Project Manager**: Permissions to create and manage projects and tasks.
- **Artist**: Access to assigned tasks and ability to update their status.
- **Viewer**: Read-only access to projects and tasks.

Assigning Security Roles to Users
---------------------------------

Security roles are assigned to users through the ftrack API by modifying the user's attributes or through the ftrack web interface. When using the API, roles can be managed via the `Session` object, which provides access to user entities and their associated roles.

Example workflow for assigning a role to a user:

1. **Retrieve the user entity** from the session using their username or ID.
2. **Modify the user's security roles** by adding or removing roles.
3. **Commit the changes** to persist the updated roles on the server.

Managing Roles Programmatically
------------------------------

Using the ftrack API's `Session` object, you can interact with user security roles as follows:

- **Fetching user roles**: Access the `security_roles` attribute of a user entity to retrieve their current roles.
- **Adding a role**: Append a new role entity to the user's `security_roles` collection.
- **Removing a role**: Remove a role entity from the user's `security_roles` collection.
- **Saving changes**: Call the `commit()` method on the session to apply changes.

Example snippet:

```python
# Assume 'session' is an authenticated ftrack_api.Session instance

# Retrieve user by username
user = session.query('User where username is "jdoe"').one()

# Retrieve a security role by name
role = session.query('SecurityRole where name is "Artist"').one()

# Assign the role to the user
user['security_roles'].append(role)

# Commit changes to the server
session.commit()
```

Best Practices
--------------

- **Least Privilege Principle**: Assign users only the roles necessary for their tasks to minimize security risks.
- **Role Auditing**: Regularly review user roles to ensure they remain appropriate as projects and teams evolve.
- **Use Groups**: Where possible, assign roles to groups rather than individual users to simplify management.
- **Automate Role Management**: Utilize scripts and API calls to automate role assignments and updates, reducing manual errors.

Troubleshooting
---------------

- **Role Changes Not Taking Effect**: Ensure that `session.commit()` is called after modifying roles.
- **Insufficient Permissions**: Verify that the API user has the necessary permissions to modify user roles.
- **Role Not Found**: Confirm that the role name used in queries matches exactly with existing roles in the system.

Conclusion
----------

Managing user security roles through the ftrack API provides a powerful way to control access and maintain security within your ftrack environment. By leveraging the `Session` object and understanding the structure of user and role entities, you can programmatically assign, modify, and audit security roles to suit your organizational needs.
