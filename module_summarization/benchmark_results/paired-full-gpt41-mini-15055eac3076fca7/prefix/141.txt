Connect to Remote Data
======================

This module provides functionality to connect to and read data from remote filesystems using URLs or file paths. It supports reading from local files as well as remote storage systems such as S3, HDFS, and others, provided the appropriate filesystem libraries are installed.

Reading Bytes from Remote Files
-------------------------------

The primary function provided is `read_bytes`, which allows you to read data from one or more files, potentially located on remote filesystems, in a chunked and efficient manner.

### Function: `read_bytes`

```python
read_bytes(
    urlpath,
    delimiter=None,
    not_zero=False,
    blocksize="128 MiB",
    sample="10 kiB",
    compression=None,
    include_path=False,
    **kwargs,
)
```

#### Description

Given a path or multiple paths, `read_bytes` returns delayed objects that read from those paths. The paths can be local file paths or remote URLs prefixed with protocols such as `s3://` or `hdfs://`. It supports glob patterns to match multiple files.

The function reads data in blocks, optionally splitting blocks on a specified delimiter to ensure that block boundaries align with logical data boundaries (e.g., lines in a text file).

#### Parameters

- **urlpath** (`str` or `list`):  
  Absolute or relative file path(s). Can include a protocol prefix like `s3://` to specify remote filesystems. Supports glob patterns or lists of paths, but all paths must use the same protocol.

- **delimiter** (`bytes`, optional):  
  A byte string delimiter (e.g., `b'\n'`) on which to split blocks of bytes. This ensures that blocks start and end at delimiter boundaries.

- **not_zero** (`bool`, optional):  
  If `True`, forces seeking past the start-of-file delimiter, effectively discarding the header.

- **blocksize** (`int` or `str`, optional):  
  The chunk size in bytes for reading data. Defaults to `"128 MiB"`. Can be specified as an integer number of bytes or a human-readable string like `"128 MiB"`.

- **sample** (`int`, `str`, or `bool`, optional):  
  Specifies whether to return a sample header from the file(s). Can be `False` to disable sampling, or an integer/string specifying the sample size (e.g., `"10 kiB"`).

- **compression** (`str` or `None`, optional):  
  Compression type such as `'gzip'` or `'xz'`. Must support efficient random access. If compression is set to `"infer"`, the compression type is inferred from the file extension.

- **include_path** (`bool`, optional):  
  If `True`, the returned data includes the file paths alongside the byte blocks.

- **kwargs** (`dict`, optional):  
  Additional options passed to the underlying filesystem connection, such as host, port, username, password, etc.

#### Returns

- **sample** (`bytes`):  
  A sample header from the file(s), useful for inferring schema or previewing data.

- **blocks** (`list` of lists of `dask.Delayed`):  
  A nested list where each inner list corresponds to a file, and each delayed object represents a block of bytes from that file.

- **paths** (`list` of `str`, optional):  
  Included only if `include_path=True`. A list of file paths corresponding to each block.

#### Usage Examples

```python
# Read blocks from local CSV files matching a glob pattern, splitting on newline
sample, blocks = read_bytes('2015-*-*.csv', delimiter=b'\n')

# Read blocks from CSV files stored in an S3 bucket
sample, blocks = read_bytes('s3://bucket/2015-*-*.csv', delimiter=b'\n')

# Read blocks and include file paths with the data
sample, paths, blocks = read_bytes('2015-*-*.csv', include_path=True)
```

### Notes

- When reading compressed files, chunked reads are not supported because random access is generally not possible. In such cases, set `blocksize=None` to read the entire file at once.

- The function uses `fsspec` to handle different filesystems transparently, allowing seamless access to local and remote data.

- The returned blocks are `dask.Delayed` objects, enabling lazy evaluation and integration with Dask's parallel computing framework.

By using `read_bytes`, users can efficiently connect to and process remote datasets in a scalable and flexible manner.
