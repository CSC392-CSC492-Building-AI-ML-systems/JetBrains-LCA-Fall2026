Generate Documentation for Code
===============================

This module provides experimental plans for data acquisition and scanning using detectors and motors. The primary functions included are `count` and `list_scan`, which facilitate taking readings from detectors and scanning over variables, respectively.

Functions
---------

count(detectors, num=1, delay=None, *, per_shot=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Take one or more readings from detectors.

**Parameters:**

- `detectors` (list): List of 'readable' objects (detectors) from which to take readings.
- `num` (int, optional): Number of readings to take; default is 1. If `None`, capture data until canceled.
- `delay` (iterable or scalar, optional): Time delay in seconds between successive readings; default is 0.
- `per_shot` (callable, optional): Hook for customizing action of inner loop (messages per step). Expected signature:
  
  ```python
  def f(detectors: Iterable[OphydObj]) -> Generator[Msg]:
      ...
  ```
- `md` (dict, optional): Metadata dictionary.

**Notes:**

- If `delay` is an iterable, it must have at least `num - 1` entries or the plan will raise a `ValueError` during iteration.

**Description:**

The `count` function yields a plan that takes readings from the specified detectors. It supports customization of the per-shot behavior via the `per_shot` callable and allows for delays between readings. Metadata about the plan execution is collected and can be extended via the `md` parameter.

list_scan(detectors, *args, per_step=None, md=None)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Scan over one or more variables in steps simultaneously (inner product).

**Parameters:**

- `detectors` (list): List of 'readable' objects (detectors) to read during the scan.
- `*args`: Variable-length argument list specifying motors and their corresponding points. For one dimension, the format is:
  
  ```python
  motor, [point1, point2, ...]
  ```
  
  For multiple dimensions, provide pairs of motors and their point lists:
  
  ```python
  motor1, [point1, point2, ...],
  motor2, [point1, point2, ...],
  ...,
  motorN, [point1, point2, ...]
  ```
  
  Motors can be any 'settable' object (motor, temperature controller, etc.).
  
- `per_step` (callable, optional): Hook for customizing action of inner loop (messages per step). Expected signature:
  
  ```python
  f(detectors, motor, step) -> plan (a generator)
  ```
  
- `md` (dict, optional): Metadata dictionary.

**Raises:**

- `ValueError`: If the number of arguments in `*args` is not even or if the lengths of all point lists are not the same.

**Description:**

The `list_scan` function yields a plan that moves multiple motors through specified points simultaneously, taking readings from detectors at each step. It validates that all point lists have the same length and supports customization of the per-step behavior via the `per_step` callable. Metadata about the scan is collected and can be extended via the `md` parameter.

**See Also:**

- `bluesky.plans.rel_list_scan`
- `bluesky.plans.list_grid_scan`
- `bluesky.plans.rel_list_grid_scan`

Modules and Imports
-------------------

- Standard libraries: `sys`, `inspect`, `itertools`, `functools`, `collections`, `time`
- Third-party libraries: `numpy`
- Conditional import of `partition` from `cytools` (preferred) or fallback to `toolz`
- Internal imports from the current package:
  - `plan_patterns`
  - `utils` (including `Msg`)
  - `preprocessors` as `bpp`
  - `plan_stubs` as `bps`

Usage Notes
-----------

- The plans use decorators from `preprocessors` to stage devices and run the plan with metadata.
- The `count` plan supports indefinite data acquisition if `num` is set to `None`.
- The `list_scan` plan requires all motors' point lists to be of equal length to ensure synchronized scanning.
- Hooks `per_shot` and `per_step` allow users to customize the behavior during data acquisition and scanning steps.

This module is designed to be part of a larger experimental control framework, facilitating flexible and customizable data collection workflows.
