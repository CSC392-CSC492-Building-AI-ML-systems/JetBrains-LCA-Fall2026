FITS Headers
============

The FITS (Flexible Image Transport System) headers module provides tools for verifying and handling FITS header data with robust error checking and flexible verification options.

Verification Classes
--------------------

The module defines custom exception and warning classes to handle verification issues:

- **VerifyError**  
  Exception class raised when verification encounters errors that cannot be ignored or fixed.

- **VerifyWarning**  
  Warning class issued for verification warnings, inheriting from `AstropyUserWarning`.

Verification Options
--------------------

Verification behavior can be controlled using a variety of options specified as strings. The available options are:

- `"ignore"`  
  Ignore verification errors.

- `"warn"`  
  Issue warnings for verification errors.

- `"exception"`  
  Raise exceptions for verification errors.

- `"fix"`  
  Attempt to fix fixable errors and raise exceptions for unfixable errors.

- `"silentfix"`  
  Attempt to fix fixable errors silently without reporting; raise exceptions for unfixable errors.

- Combinations such as `"fix+ignore"`, `"fix+warn"`, `"fix+exception"`, `"silentfix+ignore"`, `"silentfix+warn"`, `"silentfix+exception"`  
  These allow fixing errors combined with different reporting behaviors.

Verification Mechanism
----------------------

The `_Verify` class provides shared methods for verification of FITS header data. Its key method is:

- `verify(option="warn")`  
  Verifies all values in the instance according to the specified option. The `option` parameter controls how verification errors are handled and reported. It supports all options listed above.

The verification process involves:

- Running checks on header values.
- Attempting to fix fixable errors if requested.
- Reporting errors or warnings based on the chosen option.
- Raising exceptions for unfixable errors when appropriate.

Error Reporting
---------------

Verification errors are collected in an `_ErrList` object, which supports nested error messages with indentation to reflect the structure of the verification process.

- `_ErrList`  
  A specialized list subclass that holds verification errors. It supports iteration over error messages with indentation for nested errors, making it easier to understand the context of each error.

Usage Notes
-----------

- The verification options allow fine-grained control over error handling, enabling users to choose between silent fixing, warnings, exceptions, or ignoring errors altogether.
- The module uses zero-based indexing for FITS header elements.
- Warnings issued during verification are of type `VerifyWarning`.
- Exceptions raised during verification are of type `VerifyError`.

This verification framework ensures that FITS headers conform to expected standards and helps maintain data integrity by providing mechanisms to detect, report, and optionally fix errors in header data.
