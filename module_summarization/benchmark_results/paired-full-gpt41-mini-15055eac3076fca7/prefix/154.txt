Connecting Steps Together
=========================

In mflowgen, complex build flows are constructed by connecting individual *steps* together. Each step represents a discrete unit of work with defined inputs and outputs. Connecting steps involves linking the outputs of one step to the inputs of another, thereby establishing data dependencies and execution order.

Step Handles
------------

To facilitate connections, each step provides *handles* that represent its inputs and outputs. These handles are tuples that uniquely identify a particular input or output port on a step. The general form of a handle is:

```
(step_name, port_type, file_name)
```

where:

- `step_name` is the name of the step,
- `port_type` is either `'inputs'` or `'outputs'`,
- `file_name` is the name of the input or output file.

Obtaining Handles
-----------------

The `Step` class provides convenient methods to obtain these handles:

- `get_input_handle(f)`: Returns the input handle for the input file `f`.
- `get_output_handle(f)`: Returns the output handle for the output file `f`.

For convenience, shorthand methods are also available:

- `i(name)`: Equivalent to `get_input_handle(name)`.
- `o(name)`: Equivalent to `get_output_handle(name)`.

Additionally, you can retrieve all input or output handles of a step using:

- `all_input_handles()`: Returns a list of all input handles.
- `all_output_handles()`: Returns a list of all output handles.

Example:

```python
step1 = Step('step1_path')
step2 = Step('step2_path')

# Get output handle from step1
out_handle = step1.o('output_file.txt')

# Get input handle from step2
in_handle = step2.i('input_file.txt')
```

Connecting Steps
----------------

Once you have handles for the outputs and inputs, you can connect steps together using the `Graph.connect()` method (not shown here). This method takes an output handle and an input handle and creates a directed edge from the output of one step to the input of another.

This connection ensures that the output file produced by the source step is passed as input to the destination step, establishing the dependency and data flow between steps.

Summary
-------

- Steps have named inputs and outputs defined in their configuration.
- Handles uniquely identify these inputs and outputs.
- Use `get_input_handle()` and `get_output_handle()` (or their shorthand `i()` and `o()`) to obtain handles.
- Connect steps by linking output handles to input handles.
- This mechanism enables building complex, parameterized build flows by composing simple steps.
