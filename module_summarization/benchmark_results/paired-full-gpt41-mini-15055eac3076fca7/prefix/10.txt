Using metadata
==============

Metadata in the ftrack API provides a flexible way to store and retrieve additional information associated with entities in the system. This can be useful for extending the functionality of ftrack without modifying the core data model.

Accessing Metadata
------------------

Metadata can be accessed through the entities in a session. Each entity exposes a metadata interface that allows you to get, set, and delete metadata entries.

Example:

.. code-block:: python

    # Assume 'session' is an active ftrack_api.Session instance
    task = session.query('Task where id is "some-task-id"').one()

    # Get metadata value by key
    value = task.get_metadata('key_name')

    # Set metadata value
    task.set_metadata('key_name', 'value')

    # Delete metadata key
    task.delete_metadata('key_name')

Metadata keys are strings and values can be any JSON-serializable data type.

Storing Complex Data
--------------------

Since metadata values are stored as JSON, you can store complex data structures such as dictionaries and lists.

Example:

.. code-block:: python

    metadata_value = {
        'approved': True,
        'reviewers': ['user1', 'user2'],
        'notes': 'Reviewed and approved on 2024-06-01'
    }
    task.set_metadata('review_status', metadata_value)

Querying Metadata
-----------------

You can query entities based on metadata values using the ftrack query language.

Example:

.. code-block:: python

    # Find tasks where metadata key 'review_status.approved' is True
    tasks = session.query('Task where metadata.review_status.approved is true')

Best Practices
--------------

- Use metadata to store information that is specific to your workflow or integration needs.
- Avoid storing large binary data in metadata; use file attachments or external storage instead.
- Keep metadata keys consistent and well-documented to ensure maintainability.
- Use JSON-serializable data types to ensure compatibility.

Notes
-----

- Metadata changes are tracked and can be audited through the ftrack event system.
- Metadata is stored per entity and persists across sessions.
- Accessing metadata does not require additional permissions beyond those needed to access the entity itself.

For more detailed information on working with metadata and entities, refer to the ftrack API documentation and the Session class reference.
