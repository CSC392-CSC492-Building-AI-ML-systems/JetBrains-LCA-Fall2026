Contracts
=========

Interaction with Smart Contracts over Web3 Connector
----------------------------------------------------

This module provides a base class and utilities for interacting with Ethereum smart contracts using a Web3 connector. It allows you to create contract proxy classes from compiled Solidity contract ABIs, interact with deployed contracts, and deploy new contracts on the blockchain.

Contract Class
--------------

The `Contract` class serves as the base class for all contract proxy classes. These proxy classes are typically created using the `construct_contract_factory` function, which takes compiled Solidity contract ABI definitions as input and returns a subclass of `Contract`.

Once you have a contract proxy class, you can:

- Create a contract proxy instance for an existing deployed contract by specifying its address.
- Deploy a new smart contract to the blockchain.

### Attributes

- **web3** (class attribute): The Web3 instance used to interact with the blockchain. This must be set before creating contract instances.
- **_abi** (class or instance attribute): The contract ABI definition.
- **_code** (class or instance attribute): The contract bytecode.
- **_code_runtime** (class or instance attribute): The runtime bytecode of the contract.
- **_source** (class or instance attribute): The source code of the contract.
- **address** (instance attribute): The Ethereum address of the deployed contract.

### Initialization

```python
Contract(abi=None, address=None, code=None, code_runtime=None, source=None)
```

Create a new contract proxy object.

- `abi` (optional): Override the class-level ABI definition.
- `address` (optional): The deployed contract address as a hex string (with `0x` prefix).
- `code` (optional): Override the class-level contract bytecode.
- `code_runtime` (optional): Override the class-level runtime bytecode.
- `source` (optional): Override the class-level source code.

Raises an `AttributeError` if the `web3` attribute is not set on the class.

### Properties

- `abi`: Returns the contract ABI. Raises `AttributeError` if not specified.
- `code`: Returns the contract bytecode. Raises `AttributeError` if not specified.
- `code_runtime`: Returns the runtime bytecode. Raises `AttributeError` if not specified.
- `source`: Returns the contract source code. Raises `AttributeError` if not specified.

### Methods

#### deploy(transaction=None, args=None, kwargs=None)

Class method to deploy the contract on the blockchain.

- `transaction` (dict, optional): Transaction parameters for the deployment transaction, such as `from` address and `value`.
- `args` (tuple, optional): Positional arguments for the contract constructor.
- `kwargs` (dict, optional): Keyword arguments for the contract constructor.

Returns the hexadecimal transaction hash of the deployment transaction.

Example usage:

```python
MyContract.deploy(
    transaction={
        'from': web3.eth.accounts[1],
        'value': 12345,
    },
    args=('DGD', 18),
)
```

This will deploy the contract with the specified constructor arguments and transaction parameters, returning the transaction hash.

Notes
-----

- The ABI, bytecode, runtime bytecode, and source code can be specified either at the class level or overridden at the instance level.
- The `web3` attribute must be set on the contract class before creating instances or deploying contracts.
- The class currently raises `AttributeError` if ABI, code, runtime code, or source are not provided, but these could potentially be derived from the source code in future implementations.

Imports and Utilities
---------------------

The module imports various utilities from `eth_abi` and `web3` packages to handle ABI encoding/decoding, exceptions, encoding utilities, formatting, and event handling. These utilities support the contract interaction functionality but are not exposed directly through the `Contract` class interface.

Summary
-------

This module provides a foundational interface for working with Ethereum smart contracts in Python, enabling contract deployment and interaction through a Web3 connection. It abstracts the complexities of ABI handling and transaction management, allowing developers to focus on contract logic and usage.
