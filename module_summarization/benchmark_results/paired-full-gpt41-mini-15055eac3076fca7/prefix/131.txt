Verification Scheme for FITS Data
=================================

Overview
--------

The verification scheme implemented in this module provides a structured approach to validate FITS (Flexible Image Transport System) data. It ensures that FITS files conform to expected standards and formats, and offers mechanisms to handle detected issues through warnings, exceptions, or automatic fixes.

Verification Classes
--------------------

### VerifyError

An exception class raised when verification encounters errors that cannot be ignored or fixed automatically.

### VerifyWarning

A warning class derived from `AstropyUserWarning` used to issue warnings during verification without interrupting program execution.

Verification Options
--------------------

Verification behavior can be controlled using various options that dictate how errors are reported and whether fixable errors should be corrected automatically. The available options are:

- `ignore` : Do not report or fix any errors.
- `warn` : Issue warnings for errors.
- `exception` : Raise exceptions for errors.
- `fix` : Attempt to fix errors and raise exceptions for unfixable errors.
- `silentfix` : Attempt to fix errors silently, raising exceptions for unfixable errors.
- `fix+ignore` : Fix errors and ignore reporting.
- `fix+warn` : Fix errors and issue warnings.
- `fix+exception` : Fix errors and raise exceptions for unfixable errors.
- `silentfix+ignore` : Silently fix errors and ignore reporting.
- `silentfix+warn` : Silently fix errors and issue warnings.
- `silentfix+exception` : Silently fix errors and raise exceptions for unfixable errors.

Verification Process
--------------------

The verification process is managed by the `_Verify` class, which provides shared methods for running verification checks on FITS data structures.

### Running Verification

The `verify` method performs the verification according to the specified option:

```python
verify(option="warn")
```

- **Parameters:**
  - `option` (str): Specifies the verification mode. Must be one of the options listed above.

- **Behavior:**
  - If `ignore` is selected, verification is skipped.
  - For other options, the method performs checks and either fixes issues, issues warnings, or raises exceptions based on the option.
  - Fixable errors can be automatically corrected if the option includes `fix` or `silentfix`.
  - Reporting of errors depends on the combination of fix and report options.

### Handling Verification Results

Verification results are collected as a list of errors and messages, each indicating whether the issue was fixable. Depending on the verification option:

- Fixable errors may be corrected automatically.
- Messages may be issued as warnings.
- Exceptions may be raised to halt processing.
- Messages may be suppressed entirely (silent fix).

Error Reporting and Indexing
----------------------------

- Verification messages include detailed descriptions of errors found.
- Note that `astropy.io.fits` uses zero-based indexing for elements, which is reflected in error messages.

Error List Structure
--------------------

Verification errors are stored in a nested list structure managed by the `_ErrList` class. This structure allows hierarchical organization of errors corresponding to different levels of the FITS data structure.

- The `_ErrList` class supports iteration over error messages with indentation to reflect nesting.
- This facilitates clear and readable reporting of complex verification issues.

Summary
-------

This verification scheme provides a flexible and robust framework for validating FITS data. By supporting multiple modes of error handling and automatic fixing, it enables users to maintain data integrity while accommodating different workflows and tolerance levels for errors.

For detailed usage and examples, refer to the `astropy.io.fits` documentation on verification.
