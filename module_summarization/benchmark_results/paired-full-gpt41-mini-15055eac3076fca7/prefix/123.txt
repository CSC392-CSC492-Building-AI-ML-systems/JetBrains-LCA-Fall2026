DeleteViewMixin and WithinRoleDeleteView
=========================================

Implements the preview + confirm + delete workflow for Django views.

Overview
--------

This module provides a mixin and a concrete view class to facilitate a common pattern in web applications where a user is presented with a preview of an object, asked to confirm deletion, and then the object is deleted upon confirmation. It integrates with Django's class-based views and the django_cradmin framework to provide a consistent user experience and messaging.

DeleteViewMixin
---------------

`DeleteViewMixin` is a mixin class designed to be used with Django's generic `DeleteView` or similar views. It encapsulates the logic and context data needed to implement a preview, confirmation, and deletion workflow.

Key Features:

- **Page Title and Labels**  
  - `get_pagetitle()`  
    Returns the page title, defaulting to "Confirm delete".  
  - `get_action_label()`  
    Returns the action label, defaulting to "Delete". Used as a prefix for the page title and as the default label for the delete button.  
  - `get_delete_button_label()`  
    Returns the label for the delete button, defaulting to the action label.  
  - `get_cancel_button_label()`  
    Returns the label for the cancel button, defaulting to "Cancel".

- **Object Preview and Confirmation Message**  
  - `get_object_preview()`  
    Returns a string representation of the object to be deleted, used to preview the object in the confirmation prompt.  
  - `get_confirm_message()`  
    Returns a localized confirmation message asking the user if they are sure they want to delete the object, including the object preview.

- **Success Handling**  
  - `get_success_url()`  
    Returns the URL to redirect to after successful deletion. Defaults to the index view of the current app.  
  - `get_success_message(object_preview)`  
    Returns a localized success message indicating the object was deleted.  
  - `add_success_messages(object_preview)`  
    Adds success messages to Django's messages framework after deletion. Can be overridden to customize messaging behavior.

- **Context Data**  
  - `add_delete_view_mixin_context_data(context)`  
    Adds necessary context variables for templates, including model verbose name, success URL, object preview, page title, confirmation message, and button labels.

- **Deletion Process**  
  Overrides the `delete()` method to capture the object preview before deletion, perform the deletion, and then add success messages.

Usage Notes:

- Import this mixin via `from django_cradmin import viewhelpers` and refer to it as `viewhelpers.formview.DeleteViewMixin`.
- Designed to be combined with Django's `DeleteView` or other compatible views.

WithinRoleDeleteView
--------------------

`WithinRoleDeleteView` is a concrete view class that combines `DeleteViewMixin` with additional mixins to support role-based querysets and common Cradmin view functionality.

Features:

- Inherits from:
  - `QuerysetForRoleMixin` — to filter the queryset based on the current role.
  - `DeleteViewMixin` — to provide the preview, confirm, and delete workflow.
  - Django's generic `DeleteView`.
  - `CommonCradminViewMixin` — for common Cradmin view features.
  - `javascriptregistry.viewmixin.WithinRoleViewMixin` — to integrate JavaScript components within the role context.

- Uses the template:  
  `'django_cradmin/viewhelpers/formview/within_role_delete_view.django.html'`  
  which provides a sane base template for delete views within a Cradmin role.

- Overrides `get_context_data()` to add:
  - JavaScript registry component IDs.
  - Common Cradmin view mixin data.
  - Delete view mixin context data.

Usage Notes:

- Import this view via `from django_cradmin import viewhelpers` and refer to it as `viewhelpers.formview.WithinRoleDeleteView`.
- Suitable for applications using Cradmin roles where deletion of role-specific objects is required.

Example Workflow
----------------

1. **Preview**  
   The user is shown a page with a preview of the object to be deleted, including a confirmation message.

2. **Confirm**  
   The user confirms the deletion by clicking the delete button, or cancels the operation.

3. **Delete**  
   Upon confirmation, the object is deleted, a success message is added to the messages framework, and the user is redirected to the success URL.

Template Context Variables
--------------------------

When rendering the delete confirmation template, the following context variables are available:

- `model_verbose_name` — The verbose name of the model of the object being deleted.
- `success_url` — URL to redirect to after successful deletion.
- `object_preview` — String representation of the object, used for preview.
- `pagetitle` — The page title, typically "Confirm delete".
- `confirm_message` — The confirmation message asking the user to confirm deletion.
- `delete_button_label` — Label for the delete button, typically "Delete".
- `cancel_button_label` — Label for the cancel button, typically "Cancel".

Customization
-------------

You can customize the behavior by overriding any of the following methods in your subclass:

- `get_pagetitle()`
- `get_action_label()`
- `get_delete_button_label()`
- `get_cancel_button_label()`
- `get_object_preview()`
- `get_confirm_message()`
- `get_success_url()`
- `get_success_message(object_preview)`
- `add_success_messages(object_preview)`

This allows you to tailor the user interface and messaging to your application's needs.

Integration with Django Messages
--------------------------------

The mixin integrates with Django's messages framework to provide user feedback after deletion. By default, it adds a success message indicating the object was deleted, but this can be customized by overriding `add_success_messages()`.

Summary
-------

The `DeleteViewMixin` and `WithinRoleDeleteView` provide a robust and reusable implementation of the preview + confirm + delete workflow, integrating seamlessly with Django's class-based views and the django_cradmin framework. They simplify the creation of delete views that require user confirmation and consistent messaging, especially in applications with role-based access control.
