Header Interface Transition Guide
==================================

Overview
--------

This guide provides an overview of the verification framework used in the header interface, focusing on the transition to a more robust and flexible verification system. The verification system is designed to check the integrity and correctness of header data, report issues, and optionally fix fixable problems.

Verification Framework
----------------------

The verification framework is centered around the `_Verify` class, which provides shared methods for verifying header data. Verification is performed by calling the `verify` method with a specified option that controls how errors are handled and reported.

Verification Options
--------------------

The `verify` method accepts an `option` parameter that determines the behavior of the verification process. The available options are:

- `"ignore"`: Do not report or fix any errors.
- `"warn"`: Report errors as warnings.
- `"exception"`: Raise exceptions on errors.
- `"fix"`: Attempt to fix fixable errors and raise exceptions on unfixable errors.
- `"silentfix"`: Attempt to fix fixable errors silently without reporting.
- Combinations such as `"fix+warn"`, `"fix+ignore"`, `"silentfix+warn"`, etc., allow fine-grained control over fixing and reporting behavior.

Verification Process
--------------------

1. **Running Verification**  
   The `verify` method calls an internal `_verify` method (to be implemented by subclasses) that performs the actual checks and returns a list of errors.

2. **Error Handling**  
   Errors are categorized as fixable or unfixable. Depending on the verification option:
   - Fixable errors may be automatically fixed.
   - Unfixable errors may trigger warnings or exceptions.
   - Errors may be reported or suppressed based on the option.

3. **Error Reporting**  
   Errors are collected and formatted into messages. These messages include details about the error and notes on indexing conventions (e.g., zero-based indexing).

Error and Warning Classes
-------------------------

- `VerifyError`: Exception class raised for verification errors when the option demands exceptions.
- `VerifyWarning`: Warning class used to issue warnings about verification issues.

Error List Structure
--------------------

Verification errors are stored in an `_ErrList` object, which is a specialized list designed to hold nested error messages. This structure allows errors to be organized hierarchically, reflecting the nested nature of header data.

Usage Notes
-----------

- The verification system is flexible and allows users to choose how strictly to enforce header correctness.
- The combination options provide a way to fix errors automatically while controlling whether and how errors are reported.
- The system uses zero-based indexing for error messages, which is important to keep in mind when interpreting error locations.

Summary
-------

The header interface verification framework provides a comprehensive and configurable approach to ensuring header data integrity. By using the `verify` method with appropriate options, users can detect, report, and fix header issues in a manner that best suits their workflow and requirements.
