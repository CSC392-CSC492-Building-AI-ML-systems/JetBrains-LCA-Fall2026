w_init — Initialize a new WEST simulation
==========================================

Synopsis
--------

.. code-block:: console

    w_init [OPTIONS]

Description
-----------

The `w_init` command initializes a new WEST simulation by creating the WEST HDF5 file and preparing the first iteration's segments.

Initial states are generated from one or more "basis states," which can be specified either by providing a file with the `--bstates-from` option or by one or more `--bstate` arguments. If neither `--bstates-from` nor at least one `--bstate` argument is provided, a default basis state with probability one, identified by state ID zero and label "basis," will be created. A warning will be printed in this case to remind you of this default behavior.

Target states for non-equilibrium steady-state simulations can be specified either by a file with the `--tstates-from` option or by one or more `--tstate` arguments. If neither `--tstates-from` nor at least one `--tstate` argument is provided, an equilibrium simulation without any sinks will be performed.

Options
-------

General options:

- `--force`  
  Overwrite any existing simulation data.

Basis state options:

- `--bstate-file`, `--bstates-from` *BSTATE_FILE*  
  Read basis state names, probabilities, and optionally data references from *BSTATE_FILE*.

- `--bstate` *label,probability[,auxref]*  
  Add a basis state specified as a string with label, probability, and optionally an auxiliary reference. This option can be specified multiple times to add multiple basis states. Basis states specified with this option are appended after those read from a file (if any).

Target state options:

- `--tstate-file`, `--tstates-from` *TSTATE_FILE*  
  Read target state names and representative progress coordinates from *TSTATE_FILE*. WESTPA uses the representative progress coordinate of a target state and converts the entire bin containing that coordinate into a recycling sink.

- `--tstate` *label,pcoord0[,pcoord1[,...]]*  
  Add a target state specified as a string with label and one or more progress coordinates. This option can be specified multiple times to add multiple target states. Target states specified with this option are appended after those read from a file (if any).

Start state options:

- `--sstate-file`, `--sstates-from` *SSTATE_FILE*  
  Read start state names, probabilities, and optionally data references from *SSTATE_FILE*.

- `--sstate` *label,probability[,auxref]*  
  Add a start state specified as a string with label, probability, and optionally an auxiliary reference. This option can be specified multiple times to add multiple start states. Start states specified with this option are appended after those read from a file (if any).

Other options:

- `--segs-per-state` *N*  
  Initialize *N* segments from each basis state. Default is 1.

- `--no-we`, `--shotgun`  
  Do not run the weighted ensemble bin/split/merge algorithm on newly-created segments.

Work Manager Options
--------------------

Additional options related to work managers can be specified; these are added automatically by the command and can be viewed by running `w_init --help`.

Examples
--------

Initialize a simulation with basis states read from a file and 5 segments per basis state:

.. code-block:: console

    w_init --bstates-from=basis_states.txt --segs-per-state=5

Initialize a simulation with two basis states specified on the command line and no target states (equilibrium simulation):

.. code-block:: console

    w_init --bstate "stateA,0.6" --bstate "stateB,0.4"

Initialize a simulation with target states read from a file and force overwrite of existing data:

.. code-block:: console

    w_init --tstates-from=target_states.txt --force

Notes
-----

- If no basis states are specified, a default basis state with label "basis" and probability 1.0 will be created.

- Target states define recycling sinks for non-equilibrium steady-state simulations.

- The `--no-we` option disables the weighted ensemble resampling algorithm on the initial segments, which may be useful for certain initialization scenarios.
