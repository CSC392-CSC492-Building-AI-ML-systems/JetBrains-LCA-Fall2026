Model Usage
===========

The `Model` class is the core abstraction representing database tables in Tortoise ORM. It provides a rich interface for defining, querying, and manipulating data in an asynchronous environment.

Defining Models
---------------

Models are defined as Python classes inheriting from `Model`. Each attribute corresponds to a database field, which can be of various types such as `IntField`, `ForeignKeyFieldInstance`, `ManyToManyFieldInstance`, and others.

Example:

```python
from tortoise import fields
from tortoise.models import Model

class User(Model):
    id = fields.IntField(pk=True)
    username = fields.CharField(max_length=50)
    email = fields.CharField(max_length=255)
```

Field Comments
--------------

You can document model fields using special comments placed immediately before the field definition. These comments start with `#:` and support multiline descriptions. The placeholder `{model}` can be used to dynamically insert the model class name in the comment.

Example:

```python
class User(Model):
    #: The unique identifier for the {model}
    id = fields.IntField(pk=True)
    #: The username of the {model}
    username = fields.CharField(max_length=50)
```

Relationships
-------------

Tortoise ORM supports various types of relationships between models:

- **ForeignKeyFieldInstance**: Defines a many-to-one relationship.
- **OneToOneFieldInstance**: Defines a one-to-one relationship.
- **ManyToManyFieldInstance**: Defines a many-to-many relationship.

These relationships are accessed asynchronously and support lazy loading.

Relationship Accessors:

- `_fk_getter`: Retrieves the related object for a foreign key field asynchronously.
- `_fk_setter`: Sets the related object for a foreign key field.
- `_rfk_getter`: Accesses reverse foreign key relations.
- `_ro2o_getter`: Accesses reverse one-to-one relations.
- `_m2m_getter`: Accesses many-to-many relations.

Querying Models
---------------

Models provide a powerful querying interface through `QuerySet` and `QuerySetSingle`. Common methods include:

- `.filter(**kwargs)`: Filters records based on field values.
- `.first()`: Retrieves the first record matching the query.
- `.all()`: Retrieves all records.
- `.order_by(*fields)`: Orders the results by specified fields.

Ordering can be specified in the model's `Meta` class using the `ordering` attribute, which supports ascending and descending order.

Example:

```python
users = await User.filter(username__startswith="A").order_by("email").all()
```

Transactions and Concurrency
----------------------------

Tortoise ORM supports asynchronous transactions and concurrency control. Use `in_transaction` context manager to perform operations atomically.

Example:

```python
async with in_transaction() as connection:
    await User.create(username="newuser", email="new@example.com")
```

Meta Options
------------

Each model can define a nested `Meta` class to configure behavior:

- `abstract`: If `True`, the model will not create a database table.
- `db_table`: Custom database table name.
- `ordering`: Default ordering for querysets.
- `unique_together`: Specifies sets of fields that must be unique together.

Example:

```python
class User(Model):
    class Meta:
        db_table = "auth_user"
        ordering = ["username"]
        unique_together = [("username", "email")]
```

Error Handling
--------------

Tortoise ORM raises specific exceptions for various error conditions:

- `ConfigurationError`: Raised for misconfiguration issues.
- `IncompleteInstanceError`: Raised when an instance is incomplete.
- `IntegrityError`: Raised on database integrity violations.
- `OperationalError`: Raised for operational database errors.
- `TransactionManagementError`: Raised for transaction misuse.

These exceptions help in robust error handling in asynchronous applications.

Summary
-------

The `Model` class in Tortoise ORM provides a comprehensive and asynchronous interface for defining database schemas, managing relationships, querying data, and handling transactions. Its design leverages Python's async capabilities to enable efficient and scalable database operations.
