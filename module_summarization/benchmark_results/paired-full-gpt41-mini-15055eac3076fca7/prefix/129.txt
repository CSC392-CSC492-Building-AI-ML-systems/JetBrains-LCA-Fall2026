Table Data
==========

The table module provides classes and utilities for verifying and handling table data structures, ensuring data integrity and consistency through a flexible verification framework.

Verification Framework
----------------------

The verification framework is designed to check the validity of table data and handle any inconsistencies or errors according to user-specified options. It supports multiple modes of operation, including warnings, exceptions, automatic fixes, and silent fixes.

### Verification Options

The following verification options are supported:

- **ignore**: Do not report or fix any verification issues.
- **warn**: Issue warnings for verification problems.
- **exception**: Raise exceptions on verification errors.
- **fix**: Attempt to fix fixable errors and raise exceptions for unfixable ones.
- **silentfix**: Attempt to fix fixable errors silently without reporting.
- **fix+ignore**, **fix+warn**, **fix+exception**: Combine fixing with different reporting behaviors.
- **silentfix+ignore**, **silentfix+warn**, **silentfix+exception**: Combine silent fixing with different reporting behaviors.

### Verification Process

Verification is performed by the `_Verify` class, which provides shared methods for running verification checks on table data instances.

- The `verify` method accepts an `option` parameter to specify the verification behavior.
- It validates the option and executes the verification logic accordingly.
- Fixable errors can be automatically corrected if the option allows.
- Errors and warnings are reported based on the chosen option.
- Unfixable errors can raise exceptions or warnings depending on the configuration.

### Error Handling Classes

- **VerifyError**: Exception class raised for verification errors that cannot be ignored or fixed.
- **VerifyWarning**: Warning class used to issue verification warnings.

### Error List Management

The `_ErrList` class manages collections of verification errors. It supports nested error messages corresponding to different levels of the table data structure, allowing detailed and hierarchical reporting of issues.

- Errors are stored with context about the element they relate to.
- The class provides methods to iterate over error messages with appropriate indentation to reflect the nested structure.
- This facilitates clear and organized presentation of verification results.

Summary
-------

This verification system ensures that table data adheres to expected standards and formats, providing mechanisms to detect, report, and optionally fix errors. It is a crucial component for maintaining data quality and reliability in table processing workflows.
