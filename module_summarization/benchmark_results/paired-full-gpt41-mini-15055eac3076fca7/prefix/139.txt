Controlling Chunking
====================

Dask arrays are composed of many smaller NumPy arrays, called *chunks*. Chunking is a fundamental concept in Dask that allows for parallel and out-of-core computation by breaking large arrays into manageable pieces.

When working with Dask arrays, controlling how these chunks are formed and manipulated is crucial for optimizing performance and memory usage. This section outlines key concepts and tools related to controlling chunking in Dask arrays.

Chunking Basics
--------------

- **Chunks**: Each Dask array is divided into chunks, which are NumPy arrays or arrays from other supported backends.
- **Chunk Size**: The size of each chunk can be specified when creating a Dask array. Proper chunk size selection balances between parallelism and overhead.
- **Chunk Shape**: Chunks can have different shapes along each dimension, allowing flexibility in how data is partitioned.

Creating and Manipulating Chunks
--------------------------------

- Use functions like `dask.array.from_array` or `dask.array.from_zarr` to create Dask arrays with specified chunk sizes.
- The `chunks` parameter controls the chunk size and shape.
- Functions such as `rechunk` allow changing the chunking scheme of an existing Dask array.

Chunking and Masked Arrays
--------------------------

Dask supports masked arrays through integration with NumPy's `numpy.ma` module. Masked arrays allow for handling invalid or missing data by masking certain elements.

- Masked arrays in Dask are chunked similarly to regular arrays.
- Operations on masked arrays are performed blockwise on each chunk.
- Functions like `filled`, `masked_greater`, `masked_less_equal`, `masked_equal`, `masked_invalid`, `masked_inside`, `masked_outside`, `masked_where`, `masked_values`, and `fix_invalid` are available and operate on chunks using `map_blocks` or `blockwise`.
- These functions ensure that masking operations respect chunk boundaries and maintain chunking consistency.

Dispatch Mechanism for Chunked Operations
-----------------------------------------

Dask uses a dispatch mechanism to handle operations on arrays with different backends or types. This allows for flexible and extensible chunked computations.

- Dispatchers such as `concatenate_lookup`, `tensordot_lookup`, `einsum_lookup`, `empty_lookup`, `divide_lookup`, `percentile_lookup`, `numel_lookup`, `nannumel_lookup`, `to_numpy_dispatch`, and `to_cupy_dispatch` manage how operations are performed on chunks.
- This mechanism enables Dask to optimize chunked operations depending on the array type and backend.

Best Practices for Controlling Chunking
---------------------------------------

- Choose chunk sizes that fit comfortably in memory but are large enough to amortize overhead.
- Use rechunking sparingly, as it can be expensive.
- When working with masked arrays, ensure that masking operations are compatible with chunk shapes.
- Leverage Dask’s dispatch system to extend or customize chunked operations for specialized array types.

Summary
-------

Controlling chunking in Dask arrays is essential for efficient computation. By understanding how chunks are created, manipulated, and processed—especially in the context of masked arrays and dispatch mechanisms—users can optimize their workflows for performance and scalability.
