Feature Extraction Module
=========================

Overview
--------

The `feature_extraction` module provides utilities to create feature extractors from PyTorch models using the FX toolkit. It enables users to trace models and extract intermediate features by specifying nodes or modules of interest. This is particularly useful for tasks such as transfer learning, debugging, and model introspection.

Key Components
--------------

### LeafModuleAwareTracer

`LeafModuleAwareTracer` is a subclass of `torch.fx.Tracer` that allows specifying a set of leaf modules. Leaf modules are modules that should not be traced through; instead, they are treated as atomic units in the traced graph. This results in a graph where calls to these leaf modules' forward methods are represented as single nodes.

- **Initialization**: Accepts a `leaf_modules` argument, which is a tuple or list of module classes to treat as leaves.
- **Behavior**: Overrides `is_leaf_module` to return `True` for modules in the specified leaf modules set.

### NodePathTracer

`NodePathTracer` extends `LeafModuleAwareTracer` and enhances tracing by recording the qualified names of nodes in the traced graph. The qualified name is a dot-separated path representing the hierarchy from the top-level module down to the leaf operation or module, excluding the top-level module name itself.

Features:

- Maintains a mapping `node_to_qualname` from FX nodes to their qualified names.
- Ensures unique node names by appending suffixes like `_1`, `_2` for duplicates.
- Overrides `call_module` to track the current module's qualified name during tracing.
- Overrides `create_proxy` to record the qualified name for each operation node.

This tracer is useful for generating feature extractors that can refer to intermediate nodes by their hierarchical names.

Functions
---------

The module exposes the following functions (not fully shown in the provided code snippet but typically included):

- `create_feature_extractor(model: nn.Module, return_nodes: Dict[str, str], *, node_names: Optional[List[str]] = None, leaf_modules: Optional[List[nn.Module]] = None) -> nn.Module`

  Creates a new module that returns intermediate features from the specified nodes or modules in the original model.

- `get_graph_node_names(graph_module: fx.GraphModule) -> List[str]`

  Returns a list of node names present in the FX graph module, useful for identifying valid nodes to extract.

Usage Example
-------------

```python
import torch
from torchvision.models import resnet18
from feature_extraction import create_feature_extractor

# Load a pretrained model
model = resnet18(pretrained=True)

# Specify the nodes from which to extract features
return_nodes = {
    'layer1.0.relu': 'feat1',
    'layer3.5.relu': 'feat2',
}

# Create a feature extractor
feature_extractor = create_feature_extractor(model, return_nodes)

# Prepare input tensor
input_tensor = torch.randn(1, 3, 224, 224)

# Extract features
features = feature_extractor(input_tensor)

print(features['feat1'].shape)  # Shape of features from layer1.0.relu
print(features['feat2'].shape)  # Shape of features from layer3.5.relu
```

In this example, `create_feature_extractor` returns a new module that outputs a dictionary containing the intermediate activations from the specified nodes. This allows easy access to features at various depths of the model without modifying the original architecture.

Notes
-----

- The tracing mechanism relies on PyTorch FX and may not support all dynamic control flows.
- Specifying appropriate leaf modules can improve tracing performance and clarity.
- Node names used in `return_nodes` should correspond to valid nodes in the FX graph; use `get_graph_node_names` to inspect available nodes.

This module is part of the torchvision library and is designed to facilitate advanced model introspection and feature extraction workflows.
