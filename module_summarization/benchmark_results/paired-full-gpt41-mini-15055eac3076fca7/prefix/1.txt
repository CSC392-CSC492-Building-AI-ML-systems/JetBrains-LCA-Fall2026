Using Custom Attributes
=======================

ftrack allows you to extend the data model of your entities by adding custom attributes. Custom attributes enable you to store additional information specific to your project or pipeline needs directly on entities such as tasks, assets, or shots.

Defining Custom Attributes
--------------------------

Custom attributes can be defined through the ftrack web interface or via the API. When creating a custom attribute, you specify its name, type, and optionally other properties such as default values or constraints.

Common attribute types include:

- String
- Number (integer or float)
- Boolean
- Date/time
- Enumeration (list of predefined values)
- User (reference to an ftrack user)
- Asset (reference to an asset entity)

Using Custom Attributes in Code
-------------------------------

Once a custom attribute is defined on an entity type, you can access and modify it through the ftrack API just like any built-in attribute.

Example:

```python
import ftrack_api

# Create a session
session = ftrack_api.Session()

# Query an entity, for example a task
task = session.query('Task where id is "some-task-id"').one()

# Access a custom attribute named 'myCustomAttribute'
value = task['myCustomAttribute']

# Modify the custom attribute
task['myCustomAttribute'] = 'New Value'

# Commit changes to the server
session.commit()
```

Notes:

- Accessing a custom attribute that does not exist on the entity will raise a KeyError.
- Custom attributes are automatically fetched when accessed if the session is configured with `auto_populate=True` (default).
- Changes to custom attributes must be committed explicitly using `session.commit()` to persist them on the server.

Creating Custom Attributes Programmatically
-------------------------------------------

While the ftrack API primarily supports managing entities and their attributes, creating or modifying the schema (including adding custom attributes) is typically done through the ftrack web interface or administration tools.

If you need to automate schema changes, consider using ftrack's schema management tools or scripts provided by ftrack or third parties.

Best Practices
--------------

- Use clear and descriptive names for custom attributes to ensure they are easily understood by all users.
- Document the purpose and expected values of custom attributes within your team or project documentation.
- Avoid overloading entities with too many custom attributes; keep the data model as simple as possible.
- Validate custom attribute values in your application code to maintain data integrity.

Troubleshooting
---------------

- If a custom attribute does not appear on an entity, verify that it has been correctly defined for that entity type.
- Ensure your session has the necessary permissions to read and write custom attributes.
- If changes to custom attributes are not saved, confirm that `session.commit()` is called after modifications.

Conclusion
----------

Custom attributes provide a flexible way to tailor the ftrack data model to your specific requirements. By leveraging them, you can enrich your project data and integrate ftrack more deeply into your production pipeline.
