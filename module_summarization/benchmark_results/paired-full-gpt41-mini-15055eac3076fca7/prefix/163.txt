Tensor Attributes
=================

Tensor attributes are metadata associated with tensors that describe their properties and behavior within the OneFlow MLIR dialect. These attributes provide essential information for tensor manipulation, optimization, and code generation.

Common Tensor Attributes
------------------------

- **shape**  
  Specifies the dimensions of the tensor. It is typically represented as a list of integers, where each integer corresponds to the size of the tensor along a particular dimension.

- **dtype**  
  Defines the data type of the tensor elements, such as `float32`, `int64`, or other supported types. This attribute is crucial for type checking and ensuring compatibility across operations.

- **layout**  
  Describes the memory layout or ordering of the tensor elements. Common layouts include row-major or column-major, but custom layouts may also be specified depending on the target hardware or optimization strategies.

- **device**  
  Indicates the device on which the tensor resides, such as CPU, GPU, or other accelerators. This attribute helps in managing data locality and optimizing execution.

- **requires_grad**  
  A boolean attribute that specifies whether the tensor requires gradient computation for automatic differentiation. This is important for training machine learning models.

- **stride**  
  Provides the stride information for each dimension of the tensor, which defines how many elements to skip in memory to move to the next element along a dimension. This is useful for advanced indexing and memory layout optimizations.

Usage in OneFlow MLIR Dialect
-----------------------------

In the OneFlow MLIR dialect, tensor attributes are used extensively to define the semantics of tensor operations and to enable various compiler optimizations. Attributes are attached to tensor types or operations to convey additional information that cannot be expressed by the type system alone.

For example, when defining a tensor operation, attributes such as `shape` and `dtype` ensure that the operation is well-formed and that the resulting tensor has the expected properties. The `device` attribute allows the compiler to generate code that targets the appropriate hardware backend.

Extensibility
-------------

The tensor attribute system in OneFlow MLIR is designed to be extensible, allowing new attributes to be added as needed to support emerging hardware features or optimization techniques. Custom attributes can be defined and attached to tensors or operations to carry domain-specific information.

Summary
-------

Tensor attributes are a fundamental part of the OneFlow MLIR dialect, providing detailed metadata about tensors that enable correct and efficient computation. Understanding and utilizing these attributes is key to leveraging the full power of the OneFlow compiler infrastructure.
