Working with Entities
=====================

Introduction
------------

Entities are the fundamental building blocks within the ftrack API, representing various objects such as projects, tasks, assets, and users. Working with entities allows you to interact programmatically with the ftrack server, enabling automation, integration, and customization of your production workflows.

Session and Entity Interaction
------------------------------

To work with entities, you first need to establish a session with the ftrack server. The `Session` object represents an isolated connection to the server and provides access to entities and other API features.

Creating a Session
~~~~~~~~~~~~~~~~~~

A session is created by specifying the server URL, API key, and API user credentials. These can be provided explicitly or through environment variables:

- `FTRACK_SERVER`: URL of the ftrack server.
- `FTRACK_API_KEY`: API key for authentication.
- `FTRACK_API_USER`: Username of the ftrack user.

Example:

```python
import ftrack_api

session = ftrack_api.Session(
    server_url='https://your.ftrack.server',
    api_key='your_api_key',
    api_user='your_username'
)
```

Auto-population of Entity Attributes
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

By default, the session is configured with `auto_populate=True`. This means that when you access an attribute of an entity that has not yet been fetched, the API will automatically retrieve it from the server. This behavior can be toggled on the session object if needed.

Accessing Entities
~~~~~~~~~~~~~~~~~~

Entities can be accessed and queried through the session. For example, to retrieve a project by its name:

```python
project = session.query('Project where name is "My Project"').one()
```

Or to get a list of tasks under a project:

```python
tasks = session.query('Task where project.id is "{}"'.format(project['id'])).all()
```

Entity Attributes
~~~~~~~~~~~~~~~~~

Entities have attributes that describe their properties and relationships. Attributes can be accessed like dictionary keys or object attributes:

```python
print(project['name'])
print(project.name)
```

Modifying Entities
~~~~~~~~~~~~~~~~~~

Entities can be modified by setting their attributes and then committing the changes to the server:

```python
project['description'] = 'Updated project description'
session.commit()
```

Creating New Entities
~~~~~~~~~~~~~~~~~~~~~

New entities can be created using the session's `create` method:

```python
new_task = session.create('Task', {
    'name': 'New Task',
    'project': project
})
session.commit()
```

Deleting Entities
~~~~~~~~~~~~~~~~~

Entities can be deleted by calling the `delete` method on the entity and committing the session:

```python
task_to_delete.delete()
session.commit()
```

Caching
-------

The session supports caching of entities to improve performance and reduce server load. You can provide a custom cache implementation or use the default layered cache with an in-memory cache on top.

Event Hub Integration
---------------------

The session can automatically connect to an event hub to publish and subscribe to events related to entities. This allows for real-time updates and integration with other systems.

Plugins
-------

The session supports plugins that can extend its functionality, including those that operate on entities. Plugins can be discovered and registered via specified plugin paths.

Summary
-------

Working with entities in the ftrack API involves:

- Establishing a session with the server.
- Querying, creating, modifying, and deleting entities.
- Utilizing automatic attribute population.
- Leveraging caching for performance.
- Integrating with the event hub for real-time event handling.
- Extending functionality through plugins.

This powerful API enables flexible and efficient management of your production data within ftrack.
