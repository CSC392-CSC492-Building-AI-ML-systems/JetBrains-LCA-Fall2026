w_fork Command
==============

Overview
--------

The `w_fork` command prepares a new weighted ensemble simulation by branching off from an existing simulation at a specified iteration. It generates a new HDF5 file representing the new simulation. This is useful for restarting or branching simulations from a particular point in a completed or ongoing weighted ensemble simulation.

In the case of executable propagation, users are responsible for setting up the new simulation directory appropriately. This includes making the restart data from the original simulation's specified iteration available as the initial state data for the new simulation. The command creates a mapping between the old simulation segments and the new simulation initial states, which is saved both in the new HDF5 file and as a flat text file to assist with this process.

Target states and basis states for the new simulation are copied from those in the original simulation.

Usage
-----

```
w_fork [OPTIONS]
```

Options
-------

- `-i`, `--input INPUT_H5FILE`  
  Specify the input HDF5 file from which to create the new simulation. If not provided, the input file is read from the configuration file.

- `-I`, `--iteration N_ITER`  
  Specify the iteration number from which to take the initial distribution for the new simulation. Defaults to the last complete iteration of the input simulation.

- `-o`, `--output OUTPUT_H5FILE`  
  Specify the filename for the new simulation HDF5 file. Defaults to `forked.h5`.

- `--istate-map ISTATE_MAP`  
  Write a text file describing the mapping of existing segments to new initial states. Defaults to `istate_map.txt`.

- `--no-headers`  
  Do not write a header line to the initial state mapping text file.

Description
-----------

`w_fork` opens the specified input HDF5 file and reads the weighted ensemble simulation data at the specified iteration (or the last complete iteration by default). It then creates a new HDF5 file for the forked simulation.

The command copies the target states and basis states from the original simulation to the new simulation.

For each segment in the specified iteration of the original simulation, `w_fork` creates a corresponding initial state and a new segment in the forked simulation. Each new initial state is marked as a restart state and prepared for use in iteration 1 of the new simulation. The new segments are initialized with the appropriate weights and parentage information, and their progress coordinates are set based on the final progress coordinates of the original segments.

A mapping between the old segments and the new initial states is generated and saved both in the new HDF5 file and as a text file (by default `istate_map.txt`). This mapping facilitates the preparation of restart data for the new simulation.

Notes
-----

- It is the user's responsibility to ensure that the restart data from the original simulation's iteration is available and correctly linked for the new simulation when using executable propagation.

- Further adjustments to the initial states or segments can be made using other tools such as `w_binning`.

Examples
--------

Create a forked simulation from iteration 10 of an existing simulation stored in `sim.h5`, saving the new simulation as `forked_sim.h5`:

```
w_fork -i sim.h5 -I 10 -o forked_sim.h5
```

Create a forked simulation using the default last iteration, and write the initial state mapping to a custom file without headers:

```
w_fork --istate-map custom_map.txt --no-headers
```

Logging
-------

The command logs its progress and any issues under the logger named `w_fork`.

See Also
--------

- `w_binning` — for adjusting initial states and segments after forking.

- Weighted ensemble simulation documentation for details on simulation setup and restart procedures.
